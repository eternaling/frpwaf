首次使用引导 完成以下两步，WAF 才会真正生效

本插件依附 frp 服务端运行，需先完成：① frp 管理——安装并启动 frps； ② frps 集成——把 WAF 回调（httpPlugins）注入 frps 配置并重启。 两步都完成后，frps 的每个新连接才会经过本插件的准入决策（黑白名单 / 自动封禁 / 内核封禁等）。

内核级封禁 检测中…

把黑名单与生效中的封禁同步到 ipset + iptables，被禁 IP 的数据包在内核层直接丢弃，连不到 frps，因此「连接数」不再增长，也节省 frps/CPU 资源。
说明：frp 的插件钩子是应用层准入，被拒的连接其 TCP 仍会被内核接受，所以仅靠插件拦截时计数仍会持续上涨——这正是本功能要解决的问题。

代理级冷却拦截 分布式突发处置，默认关闭

当某代理在窗口内同时满足「连接数 ≥ 下限、独立 IP ≥ 下限、仅 1 次 IP 占比 ≥ 阈值」时进入冷却：冷却期内该代理的新出现 IP 首连被拒（原因 proxy_cool），已见过的 IP 放行。适用于「海量不同 IP × 每 IP 仅 1 次」的分布式爬虫/扫描。
误伤提示：出口 IP 变化的真实用户（移动网络切换、动态 IP、CDN 回源）可能被拒。建议先观察「突发观测」1-2 天，确认流量性质且可接受偶发误伤后再启用；白名单 IP 不受影响。

静态拦截页 被封 IP 展示页面，默认开启

frp 回调只能 allow/reject、无法返回 HTML；frps 的 custom404Page 只对未注册域名生效。故「被封 IP 展示页面」由本服务在内核层改道实现。
内核级封禁开启 → DROP 静默丢包（无页面）；内核级封禁关闭 + 拦截页开启 → iptables REDIRECT 展示页面；两者都关 → 仅应用层拒绝。
