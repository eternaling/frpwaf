# 09 · 认证与安全

## 1. 管理面板认证

### 1.1 默认账号

- 默认 `admin` / `123456`（`config.DEFAULTS`），与 `password_changed=false` 配套。
- **首次登录强制改密**：`password_changed=false` 时，登录成功后除
  `POST /api/login`（在门禁之前处理）、`POST /api/password`、`GET /api/overview`
  与静态页之外的 `/api/*` 一律返回 `403 {"msg":"需先修改默认口令"}`；
  网页端会直接弹出改密门禁（需输入原口令 + 新口令两次）。
  注：门禁白名单实际只有 `/api/password` 与 `/api/overview` 两项，
  `POST /api/logout` 也会拿到 403（前端包裹了容错，仍会回到登录页）。
- **改回默认值会被强制重改**：`/api/password` 拒绝把新口令设为 `123456`，且
  `normalize_password_flag` 按“口令是否仍等于出厂值”推导标志——即使通过手改 json /
  插件端把口令改回 `123456`，门禁也会重新生效。
- 仍需安装后立即改密：强制改密只保护「默认口令」这一种情形，弱口令（如 `admin888`）不在其内。
- 用户名规则：≥2 位，字符集 `^[A-Za-z0-9_.@-]+$`。
- 密码规则：≥4 位。

### 1.2 会话令牌（`app/auth.py`）

```
token = base64url(payload).HMAC-SHA256(payload, secret)
payload = {"u": user, "exp": 过期时间戳}
```

- 签名密钥 `secret`：首次生成（`secrets.token_hex(32)`）后**固定**。
- 有效期 `SESSION_TTL = 12 小时`。
- 校验用 `hmac.compare_digest`（**恒定时间比较**，防时序侧信道）。
- 无需数据库；进程重启后旧会话**仍有效**（secret 固定），除非改密/换 secret。
- Web 端或插件端修改用户名/密码成功时原子保存新 `secret`，全部旧会话立即失效；
  认证校验直接读取磁盘配置（不使用决策路径的 1 秒缓存），跨进程改密后
  下一次请求也会使用新密钥；普通配置保存和服务重启不轮换密钥。

### 1.3 Cookie

- 名称 `frpwaf_sid`；
- 属性 `Path=/; HttpOnly; SameSite=Lax`；
- **`Secure` 默认不加**：面板走明文 HTTP（7080），若加 `Secure` 浏览器在
  `http://` 下不会回传 Cookie，会「登录成功却立刻 401」。仅当请求经 HTTPS
  （反向代理设 `X-Forwarded-Proto: https`）或配置显式 `cookie_secure=true` 时才加。

### 1.4 登录限速（`daemon`，双维度 + 落盘）

两层闸门，**两个维度同时生效**：

| 维度 | 阈值 | 处置 |
|---|---|---|
| 来源 IP | 窗口 300 秒内失败 10 次 | 锁定 **300 秒起，每次重复触发翻倍，封顶 3600 秒** |
| 全局失败总数 | 窗口 300 秒内共 300 次 | 进入全局冷却（60 秒起指数退避），冷却期内**非本机来源一律拒绝** |
| 本机例外 | `127.0.0.1` / `::1` / `::ffff:127.0.0.1` | 不参与全局冷却（避免把自己锁在门外）；本机登录成功会清零全局冷却等级 |

- 锁定期间登录返回 `429` + `Retry-After`（提示剩余秒数）。
- 失败响应前 `sleep(0.3)` 降低爆破速率。
- 来源 IP 维度单次成功登录清除该 IP 计数；字典有界：>5000 条时先清过期项，仍超则按窗口
  起点淘汰最旧的一半。
- **失败计数落盘** `data/login_guard.json`（按 2 秒节流、原子替换、`chmod 600`）：
  重启**不再清零**（旧实现是纯内存，攻击者把服务打重启就拿到新一轮配额）。
- 登录成功/失败/被限速/全局冷却均写运行日志。

> 为什么要全局维度：单 IP 维度可被分布式来源绕开（每 IP 10 次 × 5000 个 IP = 5 万次尝试，
> 单 IP 维度永远不触发）。

## 2. 密码 / 账号修改

两端逻辑一致（`auth.change_credentials` 与 `frpwaf_main.change_admin_pwd`）：

- `old`（原密码）**必填校验**，用 `hmac.compare_digest`；
- 可选 `old_user`（原用户名）二次校验；
- `new_user`（新用户名）可选；`new`（新密码）可选；二者不可都空。

## 3. 密钥 / 密码保护

### 3.1 文件权限

- `data/frpwaf.json`：`chmod 600`（含 `admin_password`、`secret`、`ai_api_key`）。
- `data/frpwaf.db`（+ `-wal`/`-shm`）：`chmod 600`。
- 插件安装时 `.py`/`.json`/`index.html` 置 `600`。

### 3.2 敏感字段掩码与回写丢弃

掩码常量集中在 `app/config.py`（三条写入路径共用同一份定义，不各自硬编码副本）：

```python
MASKED_VALUE = "******"
MASKED_KEYS  = ("ai_api_key", "admin_password", "secret")
```

**读（回显）侧**：`GET /api/config` 先剔除 `MASKED_KEYS` 全部键，再把 `ai_api_key` 单独回显：

- `secret` / `admin_password` **完全不返回**（键都不出现在响应里）；
- `ai_api_key` 有值时返回 `"******"`，未设置时返回 `""`。

**写（保存）侧——“回写掩码必须丢弃”**：客户端常见的动作是「读配置 → 改一项 → 整体回写」，
这会把 `******` 原样提交回来。若照写就**毁掉真实密钥/口令**（AI 审查从此静默失效、
管理员口令变成掩码字符）。因此三条写入路径（`daemon` 的 `/api/config`、插件端、
`config.save`）**遇到值等于 `MASKED_VALUE` 的机密字段一律丢弃**：

> 「丢弃」= **保留磁盘原值**，**不是清空**。要真正清空密钥，请传空串 `""`（而非 `******`）。

插件端 `get_admin` / `get_waf_info` 同样只回显 `******`（不回明文口令）；修改密码必须走
`change_admin_pwd`（需校验原密码）。这两处运行在**已登录的宝塔面板**上下文中（继承面板鉴权），
不回显是纵深防御：避免插件请求日志、浏览器网络面板、截图等场景泄露密码。
独立 Web 端则**从不**返回明文密码。

> 仍然一定要用正式密钥：面板服务端只保证不回显/不误写，不保证客户端不缓存。

### 3.3 配置写入防损坏与并发保护

插件端 `_set_cfg` 在**读取失败（文件损坏 / 并发写坏）时拒绝保存**，绝不覆盖——
避免把 `secret` / `admin_password` / `ai_api_key` 一并抹除。若缺 `secret` 则用应用
默认值补齐（生成新 secret）后再写。

`app/config.py` 的 `save(patch)` 为 **patch 语义 + 并发保护**：进程内线程锁 +
跨进程文件锁（`fcntl.flock` / `msvcrt.locking`，不可用时降级）内「读磁盘现状 →
合并本次修改 → 原子替换」。WAF 守护进程（面板保存 / AI 审查）与宝塔插件进程
并发写不同字段时互不覆盖；磁盘配置损坏时抛 `ValueError` 拒绝写入。

## 4. 网络暴露面

| 路径 | 是否需要登录 | 说明 |
|---|---|---|
| `POST /frp/handler` | **否** | frps 回调，始终放行（含 `web_enabled=false` 时）；**仅接受本机来源**（127.0.0.1/::1/::ffff:127.0.0.1），非本机 403 并计入 `frp_remote_denied`。默认监听 `127.0.0.1:7082` 的**独立端口**，该监听只接受 `/frp/handler` |
| `GET /`、`/index.html` | 否（仅静态页） | 登录页/SPA |
| `POST /api/login` | 否 | 登录接口（有限速） |
| `POST /api/logout`、`GET /api/overview`、`POST /api/password` | **是**，自身不做「首登改密」拦截 | 强改密门禁白名单只有 `/api/password` 与 `/api/overview`（概览仅只读，供前端渲染引导）；`/api/logout` 不在白名单（前端已容错，仍能回到登录页） |
| `/api/*`（其余） | **是** | 需有效会话 Cookie；`password_changed=false` 时额外返回 `403 需先修改默认口令` |
| `web_enabled=false` | —— | `/`、`/index.html`、`/api/*` 一律 `403` |

> **默认值已收紧，但云安全组仍需自行确认**：面板默认只绑 `127.0.0.1`（`http_addr`），
> 开箱不会对公网暴露；但一旦你为了远程访问打开「允许远程访问」（`0.0.0.0`），
> 暴露面就完全取决于**云安全组 / 宝塔防火墙 / 主机防火墙**——程序侧不会自动限制来源，
> 请确保只放行可信 IP。若完全不需要远程管理，保持默认 `127.0.0.1` 即可（经 SSH 隧道/宝塔访问），
> 或直接关闭网页端（`web_toggle`），仅用宝塔插件端管理。

### 4.1 AI 接口的出网策略（SSRF 防护）

守护进程以 **root** 运行，而 AI 接口地址是用户在面板里填的。不校验就等于
「已登录用户可让 root 访问任意地址」：`file://` 读本机文件、`http://169.254.169.254/`
读云元数据（IMDSv1 可拿 STS 凭据）、内网管理口探测。校验实现为
`app/daemon.py::ai_url_guard`，两条路径都过：

| 时机 | 说明 |
|---|---|
| `POST /api/config` 保存 `ai_base_url` 时 | 不通过直接返回错误、不落盘（否则可先存恶意地址、再走 `/api/ai/test` 绕开） |
| 实际发起调用前 | 以防 DNS 在两次校验之间变心 |

判定步骤（顺序不可交换）：

1. **只允许 `http` / `https`**，其它 scheme（`file:` / `gopher:` / `ftp:` …）一律拒绝；
2. **先把域名解析成 IP，再按 IP 判定**——否则「公网域名 A 记录指向内网」直接绕过；
   一次解析出多个地址时，**任一不合规即整体拒绝**；
3. **永远拒绝**（硬拒，不受配置影响）：`169.254.0.0/16`（含 `169.254.169.254` 元数据）、
   `100.100.100.200/32`（阿里云元数据，经典网络）、`fd00:ec2::254/128`（AWS IPv6 元数据）、
   IPv6 链路本地 `fe80::/10`、**组播**地址、**未指定地址**（`0.0.0.0` / `::`）；
4. **私有 / 回环 / 保留地址**由配置 `ai_allow_private` 决定：
   - `true`（默认）：**允许**——AI 网关普遍是内网自建（如 `http://127.0.0.1:3000`），
     一刀切禁私有地址等于直接废掉该功能；
   - `false`：只允许公网地址。

> IPv4-mapped IPv6（`::ffff:1.2.3.4`）会先**摊平为 IPv4** 再比较，否则同一地址换个写法就能绕过网段判定。
>
> 失败时回显的错误也不带响应体：只回 `HTTP 4xx/5xx` 状态码，
> 否则 SSRF 即使被拦在「访问」这一步，也能被当成读数据的通道。
>
> 配置键完整说明见 [04 §3.11](04-数据模型与配置项.md)。

## 5. 请求处理的安全加固

- 请求体上限 **2MB**（`_body()` 超限抛错），防超大请求耗尽内存；
- socket `timeout=30`，缓解 slowloris 慢连接；
- **并发硬闸门**：面板与回调各有独立配额（默认 `max_concurrent=96` /
  `handler_max_concurrent=32`，钳制 `[8,512]`），超限的连接**直接 `shutdown`+`close`
  而不排队**（排队的连接本身也占 fd，只会把耗尽时间推迟；回 503 也要占一个线程与 fd）。
  `frpwaf.init` 启动前 `ulimit -n 8192`，避免默认 1024 的 fd 上限被慢连接打满后
  `accept` 失败连带 frps 回调失败（fail-closed 全站拒连）；
- 静态资源路径做**目录穿越防护**（`os.path.abspath` 前缀校验）；
- 默认访问日志静音（`log_message` 空实现），仅记录关键事件到 `frpwaf.log`；
- **500 响应不回显异常细节**：未认证可达的请求处理异常仅把 traceback 写入
  `frpwaf.log`，响应固定为 `{"code":500,"msg":"服务器内部错误"}`（防内部结构泄露）；
- 登录限速表有**硬上限**（超 5000 条先清过期、再按窗口起点淘汰最旧一半），
  防止分布式伪造来源把内存表撑爆；
- **登录失败计数落盘**（`data/login_guard.json`，`chmod 600`），重启不清零；
- 决策异常时**放行**并打印堆栈（fail-open，避免 WAF 小 bug 拖垮业务）；
  进程不可达则由 frps 的 fail-closed 兜底（见 [03-工作原理与准入决策.md](03-工作原理与准入决策.md)）。
  注：**地址解析失败**是另一回事——默认同样放行（`invalid-ip-pass`）但会计数，
  想要「解析不出就拒连」（`invalid-ip-strict`）请置 `strict_addr=true`，见
  [04 §3.11.1](04-数据模型与配置项.md)。

## 6. 运行日志中的隐私

- 登录失败只记「来源 IP + 用户名」，不记密码；
- 拒绝连接记「IP + 代理 + 原因」；
- **不打印任何密钥 / token**。

### 6.1 日志注入防护（不可信字段转义 + 截断）

日志是安全产品的**取证依据**，但多个字段是外部可控的：
`proxy_name` / `proxy_type` / `user` 均来自 frpc 客户端的 `NewUserConn` 回调，
`ai_base_url` 等来自面板请求体。其中含一个 `\n` 就能**凭空插入一整行看似可信的日志**
（如伪造一条 `[审计]` 记录），而 `/api/syslog` 与插件端「运行日志」页会原样展示——
取证链直接被污染。

因此日志入口统一做净化（`daemon._log`，`_audit` 也走它）：

| 处理 | 规则 |
|---|---|
| 行分隔符 | `\r` / `\n` 转义成字面量 `\\r` / `\\n`（**不再拆行**） |
| 其它控制字符 | `\x00-\x08` / `\x0b` / `\x0c` / `\x0e-\x1f` / `\x7f` 直接**丢弃** |
| 长度 | 不可信字段（代理名/用户名/代理类型/接口地址）截断到 **64 字符**（`_LOG_FIELD_MAX`，超出补 `...`） |

> 时间戳前缀与正常日志格式不变；日志单文件超 2MB 时**保留尾部 1MB**（避免无限增长）。
> 同一份 `data/frpwaf.log` 由守护进程与宝塔插件端共同追加写，两端日志入口都按上述口径净化，
> 否则「一端净化、一端不净化」等于把防护降到较弱的一端。

### 6.2 登录页与未登录访问

- 未登录访问 `/` 返回 `web/index.html`（SPA），前端探测 `/api/overview`：
  成功则进入主界面，`401` 则显示登录框。**未登录不会返回任何业务数据**。
- 登录接口 `/api/login` 对**任意来源**开放（否则无法登录），但受**登录限速**保护
  （见 §1.4）；失败响应前 `sleep(0.3)` 降低爆破速率。
- 独立面板「修改管理员账号」需**校验原密码**（`old` 必填），未登录无法调用。

## 7. 安全清单（部署建议）

1. 首次登录时按提示**修改默认 `admin`/`123456`**（不改则除改密/概览外全部 API 403）；
2. 保持面板默认的 `127.0.0.1` 监听；确需远程访问时，先改掉默认口令再开「允许远程访问」，
   **并自行确认云安全组 / 宝塔防火墙只放行可信 IP**；
3. 定期检查「连接日志」「封禁管理」；
4. AI 密钥仅保存在 `600` 的配置文件里，不在面板回显；
5. 内核封禁开启（`fw_sync_enabled`）以在内核层丢包；
6. 如需对外，建议前置 HTTPS 反代并设 `X-Forwarded-Proto`（此时 Cookie 会自动加 `Secure`）。
