# 04 · 数据模型与配置项

## 1. 存储概览

- 数据库：SQLite，路径 `data/frpwaf.db`（`FRPWAF_HOME` 默认 `/opt/frpwaf`）。
- 模式：**WAL**（`journal_mode=WAL`），`synchronous=NORMAL`，`busy_timeout=5000`。
- WAL 调优：`wal_autocheckpoint=512`（约 2MB 合并一次）、
  `journal_size_limit=16MB`（checkpoint 后截断）。
- 连接：全局单连接 `_conn`，`check_same_thread=False`，多线程共用；
  所有读写经 `_lock` 串行化。`_connect()` 带**自愈**：连接失效（进程重启/fd 陈旧）
  时自动重建。
- 权限：DB / `-wal` / `-shm` 文件 `chmod 600`。
- 配置：`data/frpwaf.json`，`chmod 600`。

## 2. 表结构

### 2.1 `ip_list` —— 黑/白名单

```sql
CREATE TABLE ip_list (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cidr TEXT NOT NULL,
    list_type TEXT NOT NULL DEFAULT 'black',   -- black / white
    remark TEXT DEFAULT '',
    created_at INTEGER NOT NULL,
    UNIQUE(cidr, list_type)                    -- 同一 CIDR 可同时存在于黑白名单
);
CREATE INDEX idx_ip_list_type ON ip_list(list_type);
```

> **关键设计（Bug B 修复）**：早期版本对 `cidr` 做**全局唯一**，导致同一个 CIDR
> 无法同时存在于黑名单与白名单（想「把黑名单项改判为白名单」只能先删再加，
> 且若白名单已存在该 CIDR 会插入失败）。现改为 `UNIQUE(cidr, list_type)`：
> 同一 CIDR 可分别在两个名单各存一条，判定时白名单优先。
> 旧库由 `_migrate_ip_list()` **自动迁移**（见 §4）。

- `cidr` 入库前经 `ipaddress.ip_network(cidr, strict=False)` 规范化
  （如 `1.2.3.4` → `1.2.3.4/32`，`10.0.0.0/8` 保持）。
- 重复插入（同 cidr + 同 list_type）抛 `ValueError("该条目已存在")`。

### 2.2 `conn_log` —— 连接审计日志

```sql
CREATE TABLE conn_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts INTEGER NOT NULL,
    ip TEXT NOT NULL,
    port INTEGER DEFAULT 0,
    proxy_name TEXT DEFAULT '',
    proxy_type TEXT DEFAULT '',
    user TEXT DEFAULT '',
    action TEXT NOT NULL,          -- allow / reject / rate_limit / error
    reason TEXT DEFAULT ''         -- whitelist/blacklist/banned/rate_limit/auto_ban...
);
CREATE INDEX idx_conn_log_ts ON conn_log(ts);
CREATE INDEX idx_conn_log_ip ON conn_log(ip);
CREATE INDEX idx_conn_log_ip_ts ON conn_log(ip, ts);   -- 按 IP 查最近记录（高频来源等）
```

- 每次 `NewUserConn` 回调写一条（无论放行还是拒绝）。
- `action`：实际只有 **`allow`**（放行）/ **`reject`**（拒绝）两种
  （`daemon` 写日志时按 `allow` 布尔值二选一）。
  表注释里的 `rate_limit` / `error` 是**预留值**，当前未被写入。
- `reason`：记录命中规则，常见取值 `whitelist` / `blacklist` / `banned` /
  `rate_limit` / `auto_ban` / `auto_ban_cc` / `auto_ban_scan` / `auto_ban_ssh` /
  `proxy_cool`（代理级冷却，见 §3.5.1） / `""`（正常放行）。
  （另有 `invalid-ip-pass`、`engine-error`，放行侧）。
- 保留上限由配置 `log_max_rows`（默认 50000）控制，后台线程周期裁剪。

### 2.3 `ban_log` —— 封禁记录（支持自动到期）

```sql
CREATE TABLE ban_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ip TEXT NOT NULL,              -- 单 IP 或 CIDR
    reason TEXT DEFAULT '',
    banned_at INTEGER NOT NULL,
    expire_at INTEGER NOT NULL,
    released INTEGER NOT NULL DEFAULT 0   -- 1=已释放（手动解封或到期）
);
CREATE INDEX idx_ban_log_ip ON ban_log(ip);
CREATE INDEX idx_ban_log_active ON ban_log(released, expire_at);   -- 生效封禁查询走索引
```

- **生效中** = `released=0 AND expire_at > now`。
- 到期由后台 `engine.auto_release()` 置 `released=1`（并记日志）。
- `ip` 可为 CIDR（如 `10.0.0.0/8`），支持整段临时封禁。
- 历史裁剪：后台循环调用 `store.trim_bans(20000)`，只删除最旧的已释放或
  已过期记录；生效封禁永不因历史上限删除，因此生效条目过多时总行数可能暂时超过上限。

### 2.4 `proxy_stat` —— 每个代理的累计统计

```sql
CREATE TABLE proxy_stat (
    proxy_name TEXT PRIMARY KEY,
    proxy_type TEXT DEFAULT '',
    total INTEGER NOT NULL DEFAULT 0,
    rejected INTEGER NOT NULL DEFAULT 0,
    last_ts INTEGER NOT NULL DEFAULT 0
);
```

- 由 `bump_proxy()` 用 `INSERT ... ON CONFLICT DO UPDATE` 累加。

### 2.5 `ai_review` —— AI 审查记录

```sql
CREATE TABLE ai_review (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts INTEGER NOT NULL,
    batch_id INTEGER DEFAULT 0,
    ip TEXT DEFAULT '',
    verdict TEXT DEFAULT '',        -- malicious / suspicious / benign / error / none
    reason TEXT DEFAULT '',
    action TEXT DEFAULT '',         -- banned / none / error / skip / already_banned / ban_failed
    model TEXT DEFAULT ''
);
CREATE INDEX idx_ai_review_ts ON ai_review(ts);
```

- 保留上限 5000（`trim_ai_review`）。

> 说明：`store.py` 文件头注释还提到一个 `settings`（简单键值）表，那是**预留**项，
> 当前 `SCHEMA` 中**并未创建**，无任何读写。配置统一走 `data/frpwaf.json`。

## 3. 配置项（`data/frpwaf.json`）

`app/config.py::DEFAULTS` 定义全部默认值。首次运行自动生成（含默认管理员
`admin`/`123456` 与随机 `secret`）。

**配置读写机制**：

- `load()`：以 `DEFAULTS` 为底，叠加文件内容（文件缺失则用默认；文件损坏时
  向上抛错，由调用方降级处理，**不会覆盖写坏文件**）；若缺 `secret` 则生成
  `secrets.token_hex(32)` 并落盘。
- `save(patch)`：**patch 语义 + 并发保护**——传入「本次要改的字段」而非全量配置；
  进程内线程锁 + 跨进程文件锁（`fcntl.flock` / `msvcrt.locking`，不可用时降级）内
  「读磁盘现状 → 合并 DEFAULTS/迁移/本次修改 → 原子替换（临时文件 + `os.replace`）」，
  并 `chmod 600`；写后立即 `invalidate()` 使缓存失效。
  磁盘配置损坏时抛 `ValueError` **拒绝写入**（防止抹除 `secret`/密码/密钥）。
- `get()`：带 **1 秒 TTL** 内存缓存（连接热路径每次读配置，避免每连接都读盘）；
  返回的是**副本**（`dict`）。
- 管理端修改后调用 `invalidate()` → 改完即生效（≤1 秒）。
- 插件端 `_set_cfg`：读取失败（文件损坏）时**拒绝保存**，防止抹除 `secret` 等敏感字段；
  正常路径同样走 `save(patch)` 合并语义，与 WAF 进程并发写互不覆盖。

### 3.4.1 攻击类型自动封禁（三类独立开关，默认全部开启）

在「连接数阈值」之外按攻击特征分维度检测，全部为**内存计数**（不查库），
命中阈值后才写封禁记录；白名单命中的 IP 一律不触发（见 [03](03-工作原理与准入决策.md) §4）。
三个开关**默认开启**（用户要求开箱即用，理由见 [03 §5](03-工作原理与准入决策.md)）；
开关开启时阈值/时长参数为 0、或窗口 ≤1 秒，会被视为「未设置」并在加载/保存时
自动回退下表的默认值，保证「开启即生效、无需手填参数」。

| 键 | 默认 | 说明 |
|---|---|---|
| `auto_ban_cc_enabled` | **`true`** | CC 攻击开关：同 IP 窗口内对 https/tcpmux 代理的高频新建连接（http 类型代理不触发 frp NewUserConn 回调，不参与检测） |
| `auto_ban_cc_window` | `60` | CC 统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_cc_threshold` | `300` | CC 连接数阈值（开启时 0 → 回退 300） |
| `auto_ban_cc_seconds` | `600` | CC 封禁时长（秒，**临时封禁**；开启时 0 → 回退 600） |
| `auto_ban_scan_enabled` | **`true`** | 端口扫描开关：同 IP 窗口内访问的不同代理数达阈值 |
| `auto_ban_scan_window` | `60` | 扫描统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_scan_threshold` | `20` | 不同代理数阈值（开启时 0 → 回退 20） |
| `auto_ban_scan_seconds` | `1800` | 扫描封禁时长（秒，**临时封禁**；开启时 0 → 回退 1800） |
| `auto_ban_ssh_enabled` | **`true`** | 敏感服务爆破开关：命中 ssh/mysql/redis 等代理的高频连接 |
| `auto_ban_ssh_window` | `60` | 爆破统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_ssh_threshold` | `20` | 爆破连接数阈值（开启时 0 → 回退 20） |

> - 敏感服务关键字按**非字母数字边界**匹配（`ssh_22`、`mysql-db`、`mongodb`、
>   `postgresql`、`elasticsearch` 命中；`wordpress`、`cardpay` 等含 `rdp` 子串的
>   普通名不会误判），且仅检测**非 HTTP 类代理**：`ssh`、`mysql`、`redis`、`rdp`、
>   `mongo`、`postgres`、`elastic`、`telnet`、`smb`、`vnc`、`ftp`。
> - 处置分档：CC / 扫描 → **临时封禁**（到期自动释放）；敏感服务爆破 → **永久黑名单**
>   （写入 `ip_list` black，内核同步 timeout=0；**黑名单开关关闭时降级为临时封禁**）。
> - 命中封禁后该 IP 的窗口**只认领一次**（计数型阈值封顶，扫描型显式记认领状态）；
>   写库失败后下一次连接可重试；窗口过期惰性重置；每类计数硬上限 5000 IP
>   （超限淘汰最旧）。

### 3.5.1 突发观测与代理级冷却（分布式突发处置）

针对「海量不同 IP × 每 IP 仅 1 次」的分布式爬虫/扫描（单 IP 维度检测按设计
不触发），按代理维度观测与处置。观测始终开启（纯内存、无副作用）；
冷却拦截**默认关闭**，误伤面见 [03 §4](03-工作原理与准入决策.md)。

| 键 | 默认 | 说明 |
|---|---|---|
| `burst_window` | `60` | 观测/判定窗口（秒），<2 视为未设置回退默认 |
| `proxy_cool_enabled` | `false` | 代理级冷却拦截开关（默认关闭） |
| `proxy_cool_min_conns` | `300` | 触发下限：窗口内连接数（开启时 0 → 回退 300） |
| `proxy_cool_uniq_threshold` | `200` | 触发下限：窗口内独立 IP 数（开启时 0 → 回退 200） |
| `proxy_cool_single_pct` | `80` | 触发下限：每 IP 仅 1 次占比（%，钳制 ≤100） |
| `proxy_cool_seconds` | `60` | 冷却时长（秒，最小 10：<10 回退默认，与引擎运行时一致） |

> - 冷却期内仅拒绝该代理的**新出现 IP**（reason `proxy_cool`），
>   进入冷却时已见过的 IP（`known` 冻结集合）放行；被拒 IP 重试不会进入
>   `known`（不可洗白）。冻结资格取 `eligible` 口径：仅「首现时代理不在冷却中」
>   的 IP 有资格——防止「爆发—停歇—再爆发」循环中上一轮被拒 IP 在重入冷却时被洗白。
> - 冷却期内累计连接数达 `proxy_cool_min_conns` 会续期（覆盖观测窗口滚动）；
>   条件消失后到期自然失效；开关关闭时立即清空冷却状态。
> - 冷却**不写** `ban_log`（代理级、短时、自愈的过滤，不参与内核同步）。
> - 冷却条目有硬上限（100，超限按进入时间淘汰最旧），与观测的 50 代理上限对称。

### 3.9 约束（保存/运行时的强制下限）

保存时（`/api/config`、插件端 `save_policy` / `ai_save_config`）会强制：

- `auto_ban_window` ≥ 1
- `auto_ban_cc_window` / `auto_ban_scan_window` / `auto_ban_ssh_window` ≥ 1
- `burst_window` ≥ 2；`proxy_cool_seconds` ≥ 10（与引擎运行时 `max(10, ...)` 一致）
- `proxy_cool_single_pct` ≤ 100
- `ai_interval` ≥ 60
- `ai_window` ≥ 30
- 整型字段一律 `max(0, int(...))`（不接受负值）

运行时兜底（即使配置被手工改小也安全）：

- `ai_timeout` 取 `max(15, ...)`（`ai.call_model`）；
- `ai_min_conns` / `ai_max_ips` 取 `max(1, ...)`、`ai_window` 取 `max(30, ...)`（`ai._collect`）；
- `ai_interval` 取 `max(60, ...)`（`ai.loop_forever`）；
- `ai_ban_seconds` 取 `max(60, ...)`（`frpwaf_main.ban_ip`；AI 内部 `int(...) or 1800`）。

## 4. `ip_list` 旧库自动迁移（Bug B）

`store._connect()` 在建表后调用 `_migrate_ip_list(_conn)`：

1. 读 `sqlite_master` 里 `ip_list` 的 DDL；
2. 已是 `UNIQUE(cidr, list_type)` → 跳过；
3. 检测到旧结构（含 `cidr TEXT NOT NULL UNIQUE`）→ 执行：
   - `ALTER TABLE ip_list RENAME TO ip_list_old`；
   - 建新表（新 DDL）；
   - `INSERT OR IGNORE ... SELECT` 搬运数据；
   - 删除旧表、重建 `idx_ip_list_type`；
   - 出错则**回滚**（删新表、旧表改名回来），绝不丢表。

> 迁移已在生产库上验证：4 条旧数据完整保留。迁移是一次性、幂等、可回滚的。

## 5. 统计口径（`store.stats`）

- `total_conns`：`conn_log` 总行数。
- `today_conns` / `today_rejected` / `today_uniq_ip`：**按服务器本地时区零点**计算。
  实现用 `time.mktime((y,m,d,0,0,0,...))` 取本地零点，**不是** `ts//86400*86400`
  （那是 UTC 零点，东八区 00:00–08:00 会把昨天算进今天）。
- `black_count` / `white_count`：名单条数。
- `active_bans`：生效中的封禁条数。
