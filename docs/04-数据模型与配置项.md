# 04 · 数据模型与配置项

## 1. 存储概览

- 数据库：SQLite，路径 `data/frpwaf.db`（`FRPWAF_HOME` 默认 `/opt/frpwaf`）。
- 模式：**WAL**（`journal_mode=WAL`），`synchronous=NORMAL`，`busy_timeout=5000`。
- WAL 调优：`wal_autocheckpoint=512`（约 2MB 合并一次）、
  `journal_size_limit=16MB`（checkpoint 后截断）。
- 连接：全局单连接 `_conn`，`check_same_thread=False`，多线程共用；
  所有读写经 `_lock` 串行化。`_connect()` 带**自愈**：连接失效（进程重启/fd 陈旧）
  时自动重建。
- 权限：DB / `-wal` / `-shm` 文件 `chmod 600`。
- 配置：`data/frpwaf.json`，`chmod 600`。

## 2. 表结构

### 2.1 `ip_list` —— 黑/白名单

```sql
CREATE TABLE ip_list (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cidr TEXT NOT NULL,
    list_type TEXT NOT NULL DEFAULT 'black',   -- black / white
    remark TEXT DEFAULT '',
    created_at INTEGER NOT NULL,
    UNIQUE(cidr, list_type)                    -- 同一 CIDR 可同时存在于黑白名单
);
CREATE INDEX idx_ip_list_type ON ip_list(list_type);
```

> **关键设计（Bug B 修复）**：早期版本对 `cidr` 做**全局唯一**，导致同一个 CIDR
> 无法同时存在于黑名单与白名单（想「把黑名单项改判为白名单」只能先删再加，
> 且若白名单已存在该 CIDR 会插入失败）。现改为 `UNIQUE(cidr, list_type)`：
> 同一 CIDR 可分别在两个名单各存一条，判定时白名单优先。
> 旧库由 `_migrate_ip_list()` **自动迁移**（见 §4）。

- `cidr` 入库前经 `ipaddress.ip_network(cidr, strict=False)` 规范化
  （如 `1.2.3.4` → `1.2.3.4/32`，`10.0.0.0/8` 保持）。
- 重复插入（同 cidr + 同 list_type）抛 `ValueError("该条目已存在")`。

### 2.2 `conn_log` —— 连接审计日志

```sql
CREATE TABLE conn_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts INTEGER NOT NULL,
    ip TEXT NOT NULL,
    port INTEGER DEFAULT 0,
    proxy_name TEXT DEFAULT '',
    proxy_type TEXT DEFAULT '',
    user TEXT DEFAULT '',
    action TEXT NOT NULL,          -- allow / reject / rate_limit / error
    reason TEXT DEFAULT ''         -- whitelist/blacklist/banned/rate_limit/auto_ban...
);
CREATE INDEX idx_conn_log_ts ON conn_log(ts);
CREATE INDEX idx_conn_log_ip ON conn_log(ip);
CREATE INDEX idx_conn_log_ip_ts ON conn_log(ip, ts);   -- 按 IP 查最近记录（高频来源等）
```

- 每次 `NewUserConn` 回调写一条（无论放行还是拒绝）。
- `action`：实际只有 **`allow`**（放行）/ **`reject`**（拒绝）两种
  （`daemon` 写日志时按 `allow` 布尔值二选一）。
  表注释里的 `rate_limit` / `error` 是**预留值**，当前未被写入。
- `reason`：记录命中规则，常见取值 `whitelist` / `blacklist` / `banned` /
  `rate_limit` / `auto_ban` / `auto_ban_cc` / `auto_ban_scan` / `auto_ban_ssh` /
  `proxy_cool`（代理级冷却，见 §3.5.1） / `""`（正常放行）。
  （另有 `invalid-ip-pass`、`engine-error`，放行侧）。
- 保留上限由配置 `log_max_rows`（默认 **200000**）控制，后台线程周期裁剪。

### 2.3 `ban_log` —— 封禁记录（支持自动到期）

```sql
CREATE TABLE ban_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ip TEXT NOT NULL,              -- 单 IP 或 CIDR
    reason TEXT DEFAULT '',
    banned_at INTEGER NOT NULL,
    expire_at INTEGER NOT NULL,
    released INTEGER NOT NULL DEFAULT 0   -- 1=已释放（手动解封或到期）
);
CREATE INDEX idx_ban_log_ip ON ban_log(ip);
CREATE INDEX idx_ban_log_active ON ban_log(released, expire_at);   -- 生效封禁查询走索引
```

- **生效中** = `released=0 AND expire_at > now`。
- 到期由后台 `engine.auto_release()` 置 `released=1`（并记日志）。
- `ip` 可为 CIDR（如 `10.0.0.0/8`），支持整段临时封禁。
- 历史裁剪：后台循环调用 `store.trim_bans(20000)`，只删除最旧的已释放或
  已过期记录；生效封禁永不因历史上限删除，因此生效条目过多时总行数可能暂时超过上限。

### 2.4 `proxy_stat` —— 每个代理的累计统计

```sql
CREATE TABLE proxy_stat (
    proxy_name TEXT PRIMARY KEY,
    proxy_type TEXT DEFAULT '',
    total INTEGER NOT NULL DEFAULT 0,
    rejected INTEGER NOT NULL DEFAULT 0,
    last_ts INTEGER NOT NULL DEFAULT 0
);
```

- 由 `bump_proxy()` 用 `INSERT ... ON CONFLICT DO UPDATE` 累加。

## 3. 配置项（`data/frpwaf.json`）

`app/config.py::DEFAULTS` 定义全部默认值。首次运行自动生成（含默认管理员
`admin`/`123456`、`password_changed=false` 与随机 `secret`）。

> **首次安装写配置**：`install.sh` 在 `data/frpwaf.json` **不存在**时写一份最小配置
> （`http_addr=127.0.0.1` / `http_port=7080` / `frp_handler_addr=127.0.0.1` /
> `frp_handler_port=7082` / `password_changed=false`，`chmod 600`），保证「装完就能在本机
> 打开面板」；**已存在则不覆盖**，避免升级时抹掉用户改过的监听地址 / 口令 / 名单。

**配置读写机制**：

- `load()`：以 `DEFAULTS` 为底，叠加文件内容（文件缺失则用默认；文件损坏时
  向上抛错，由调用方降级处理，**不会覆盖写坏文件**）；若缺 `secret` 则生成
  `secrets.token_hex(32)` 并落盘。
- `save(patch)`：**patch 语义 + 并发保护**——传入「本次要改的字段」而非全量配置；
  进程内线程锁 + 跨进程文件锁（`fcntl.flock` / `msvcrt.locking`，不可用时降级）内
  「读磁盘现状 → 合并 DEFAULTS/迁移/本次修改 → 原子替换（临时文件 + `os.replace`）」，
  并 `chmod 600`；写后立即 `invalidate()` 使缓存失效。
  磁盘配置损坏时抛 `ValueError` **拒绝写入**（防止抹除 `secret`/密码/密钥）。
- `get()`：带 **1 秒 TTL** 内存缓存（连接热路径每次读配置，避免每连接都读盘）；
  返回的是**副本**（`dict`）。
- 管理端修改后调用 `invalidate()` → 改完即生效（≤1 秒）。
- 插件端 `_set_cfg`：读取失败（文件损坏）时**拒绝保存**，防止抹除 `secret` 等敏感字段；
  正常路径同样走 `save(patch)` 合并语义，与 WAF 进程并发写互不覆盖。

### 3.1 监听 / 网页端

| 键 | 默认 | 说明 |
|---|---|---|
| `http_addr` | `"127.0.0.1"` | 管理面板监听地址。**默认仅本机**（旧默认 `0.0.0.0`）：面板 + 默认口令摆到公网等于把 root 级操作面开放。面板 `/api/config` 只接受 `127.0.0.1` / `0.0.0.0` / `::1` / `::` 四值（`localhost` 归一化为 `127.0.0.1`），其它地址明确报错、不静默回退；手填具体网卡地址（如 `10.0.0.5`）请直接改 json |
| `http_port` | `7080` | 面板监听端口 |
| `frp_handler_addr` | `"127.0.0.1"` | frps 回调（`POST /frp/handler`）的**独立监听地址**；`frps.toml` 的 `[[httpPlugins]]` `addr` 取此值（由插件端注入） |
| `frp_handler_port` | `7082` | 回调监听端口。与面板分端口后，面板被慢连接/扫描打满时回调仍有独立配额，不会让 frps 因回调失败而 fail-closed 拒全部连接 |
| `max_concurrent` | `96` | 面板并发闸门（每连接一个线程 = 一个 fd，超限**直接断连不回 503**：回包也要占 fd） |
| `handler_max_concurrent` | `32` | 回调并发闸门（与面板各自独立） |
| `web_enabled` | `true` | 是否启用网页端；关闭仅屏蔽 `/` 与 `/api/*`，**回调与防护照常** |
| `cookie_secure` | 不在 `DEFAULTS`（缺省即不启用） | 给会话 Cookie 加 `Secure`；**手工添加**该键并置 `true` 才生效（或经 HTTPS 反代自动加，见 [09](09-认证与安全.md) §1.3） |

> **防呆（`normalize_listen`）**：端口非法（非数字/越界）回退默认；`frp_handler_port`
> 不得等于 `http_port` 或 `block_page_port`（逐级回退 `7082` → `7083`）；两个并发上限钳到
> `[8, 512]`。`save()` 时对「面板/回调/拦截页端口两两相同」直接拒绝并报错。
> 监听地址/端口/并发上限变更后 daemon 会**立即重绑**（无需重启，失败回退旧监听）。
> fd 上限由 `frpwaf.init` 启动前的 `ulimit -n 8192` 保证。

### 3.4.1 攻击类型自动封禁（三类独立开关，默认全部开启）

在「连接数阈值」之外按攻击特征分维度检测，全部为**内存计数**（不查库），
命中阈值后才写封禁记录；白名单命中的 IP 一律不触发（见 [03](03-工作原理与准入决策.md) §4）。
三个开关**默认开启**（用户要求开箱即用，理由见 [03 §5](03-工作原理与准入决策.md)）；
开关开启时阈值/时长参数为 0、或窗口 ≤1 秒，会被视为「未设置」并在加载/保存时
自动回退下表的默认值，保证「开启即生效、无需手填参数」。

| 键 | 默认 | 说明 |
|---|---|---|
| `auto_ban_cc_enabled` | **`true`** | CC 攻击开关：同 IP 窗口内对 https/tcpmux 代理的高频新建连接（http 类型代理不触发 frp NewUserConn 回调，不参与检测） |
| `auto_ban_cc_window` | `60` | CC 统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_cc_threshold` | `300` | CC 连接数阈值（开启时 0 → 回退 300） |
| `auto_ban_cc_seconds` | `600` | CC 封禁时长（秒，**临时封禁**；开启时 0 → 回退 600） |
| `auto_ban_scan_enabled` | **`true`** | 端口扫描开关：同 IP 窗口内访问的不同代理数达阈值 |
| `auto_ban_scan_window` | `60` | 扫描统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_scan_threshold` | `20` | 不同代理数阈值（开启时 0 → 回退 20） |
| `auto_ban_scan_seconds` | `1800` | 扫描封禁时长（秒，**临时封禁**；开启时 0 → 回退 1800） |
| `auto_ban_ssh_enabled` | **`true`** | 敏感服务爆破开关：命中 ssh/mysql/redis 等代理的高频连接 |
| `auto_ban_ssh_window` | `60` | 爆破统计窗口（秒），保存时强制 ≥1 |
| `auto_ban_ssh_threshold` | `20` | 爆破连接数阈值（开启时 0 → 回退 20） |

> - 敏感服务关键字按**非字母数字边界**匹配（`ssh_22`、`mysql-db`、`mongodb`、
>   `postgresql`、`elasticsearch` 命中；`wordpress`、`cardpay` 等含 `rdp` 子串的
>   普通名不会误判），且仅检测**非 HTTP 类代理**：`ssh`、`mysql`、`redis`、`rdp`、
>   `mongo`、`postgres`、`elastic`、`telnet`、`smb`、`vnc`、`ftp`。
> - 处置分档：CC / 扫描 → **临时封禁**（到期自动释放）；敏感服务爆破 → **永久黑名单**
>   （写入 `ip_list` black，内核同步 timeout=0；**黑名单开关关闭时降级为临时封禁**）。
> - 命中封禁后该 IP 的窗口**只认领一次**（计数型阈值封顶，扫描型显式记认领状态）；
>   写库失败后下一次连接可重试；窗口过期惰性重置；每类计数硬上限 5000 IP
>   （超限淘汰最旧）。

### 3.5.1 突发观测与代理级冷却（分布式突发处置）

针对「海量不同 IP × 每 IP 仅 1 次」的分布式爬虫/扫描（单 IP 维度检测按设计
不触发），按代理维度观测与处置。观测始终开启（纯内存、无副作用）；
冷却拦截**默认关闭**，误伤面见 [03 §4](03-工作原理与准入决策.md)。

| 键 | 默认 | 说明 |
|---|---|---|
| `burst_window` | `60` | 观测/判定窗口（秒），<2 视为未设置回退默认 |
| `proxy_cool_enabled` | `false` | 代理级冷却拦截开关（默认关闭） |
| `proxy_cool_min_conns` | `300` | 触发下限：窗口内连接数（开启时 0 → 回退 300） |
| `proxy_cool_uniq_threshold` | `200` | 触发下限：窗口内独立 IP 数（开启时 0 → 回退 200） |
| `proxy_cool_single_pct` | `80` | 触发下限：每 IP 仅 1 次占比（%，钳制 ≤100） |
| `proxy_cool_seconds` | `60` | 冷却时长（秒，最小 10：<10 回退默认，与引擎运行时一致） |

> - 冷却期内仅拒绝该代理的**新出现 IP**（reason `proxy_cool`），
>   进入冷却时已见过的 IP（`known` 冻结集合）放行；被拒 IP 重试不会进入
>   `known`（不可洗白）。冻结资格取 `eligible` 口径：仅「首现时代理不在冷却中」
>   的 IP 有资格——防止「爆发—停歇—再爆发」循环中上一轮被拒 IP 在重入冷却时被洗白。
> - 冷却期内累计连接数达 `proxy_cool_min_conns` 会续期（覆盖观测窗口滚动）；
>   条件消失后到期自然失效；开关关闭时立即清空冷却状态。
> - 冷却**不写** `ban_log`（代理级、短时、自愈的过滤，不参与内核同步）。
> - 冷却条目有硬上限（100，超限按进入时间淘汰最旧），与观测的 50 代理上限对称。

### 3.7.1 静态拦截页与内核封禁联动

背景：frp 服务端插件（`httpPlugins` / `NewUserConn`）只能返回 allow/reject，**无法返回 HTML**；
frps 的 `custom404Page` 只对「Host 未匹配任何 frpc 域名」的路由失败生效（frp#5015）。
因此「被封 IP 展示页面」只能靠网络层改道：内核级封禁关闭时，用 `iptables -t nat REDIRECT`
把命中封禁的 IP 在其访问端口上引导到 daemon 提供的拦截页服务。

| 键 | 默认 | 说明 |
|---|---|---|
| `block_page_enabled` | **`true`** | 拦截页总开关（默认开启） |
| `block_page_404_enabled` | **`true`** | 404 页开关（默认开启） |
| `block_page_ban_enabled` | **`true`** | 封禁页开关（默认开启） |
| `block_page_risk_enabled` | **`true`** | 风控页开关（默认开启） |
| `block_page_port` | `7081` | 拦截页服务监听端口（与 `http_port` 解耦，避免误挡面板；非法或与 `http_port` 相同则回退默认） |
| `block_page_addr` | `"0.0.0.0"` | 拦截页服务监听地址。**故意不跟随 `http_addr`**：拦截页是给外网访客看的，面板收紧到 `127.0.0.1` 后若拦截页也跟着收紧，被封 IP 会变成连接超时而不是看到页面 |
| `block_page_redirect_ports` | `""` | REDIRECT 目标端口（逗号分隔，如 `"80,8080"`）；留空 = 自动读取 frps `vhostHTTPPort` |

语义区分（与需求 7 对应）：

| 模式 | 机制 | 被封 IP 看到 |
|---|---|---|
| `fw_sync_enabled=true` | ipset+iptables **DROP** | 连接超时，**无页面**（静默） |
| `fw_sync_enabled=false` + `block_page_enabled=true` | nat **REDIRECT** 到 `block_page_port` | 封禁页 / 风控页 |
| 两者都关 | 仅 frp 回调 reject | 连接重置，无页面 |

> 说明：拦截页服务由 daemon 在 `block_page_addr:block_page_port` 独立监听，**不受 `web_enabled` 与登录态影响**
> （否则被封 IP 无法看到页面、或与面板争抢端口）。改地址或端口后 `ensure()` 会真正重绑
> （会同时比对地址与端口）。

### 3.10 GitHub 在线升级

用于把「放到 GitHub 后通过仓库在线升级」的能力做成可配置项；仓库地址**不写死**，
留空即未配置。升级流程：检查最新 release → **选定带 sha256 锚点的发布包资产** →
下载并校验哈希（32MB 上限）→ 安全解包（96MB / 2000 文件上限）→ 结构校验
（含包内版本 == tag）→ 备份程序（不含 `data/`）→ 覆盖并清理陈旧 `.py` → 重启 → 任一步失败自动回滚。

> **零校验信息 = 拒绝升级**：发布包必须有 sha256 锚点——优先 GitHub asset `digest`，
> 其次 Release 附带的 `SHA256SUMS` / `pkg.sha256`。两者都没有时提示
> 「该发布缺少校验信息」并**拒绝升级**（这条链路以 root 覆盖 `/opt/frpwaf`，
> 无锚点等于把「上游被接管」兑换成本机 root RCE）。只有 tag 或只有 GitHub 自动源码
> tarball 的发布**不可升级**（源码 tarball 没有哈希锚点，仅用于展示/排障）。
> 另：`apply` 的仓库只取自配置 `github_repo`，请求体传的 `repo` 不生效；
> 升级备份只保留最近 3 份（`data/upgrade_backup/`）。详见 [13](13-变更历史与版本.md) §10。

| 键 | 默认 | 说明 |
|---|---|---|
| `github_repo` | `"eternaling/frpwaf"` | GitHub 仓库 `owner/repo`（默认本项目公开仓库，可改为自己的 fork）；置空 = 未配置 |
| `github_last_check` | `0` | 上次检查更新时间戳 |
| `github_last_result` | `""` | 上次检查结果摘要（前端展示） |
| `github_last_ok` | `true` | 上次检查是否成功 |

### 3.9 约束（保存/运行时的强制下限）

保存时（`/api/config`、插件端 `save_policy` / `ai_save_config`）会强制：

- `auto_ban_window` ≥ 1
- `auto_ban_cc_window` / `auto_ban_scan_window` / `auto_ban_ssh_window` ≥ 1
- `burst_window` ≥ 2；`proxy_cool_seconds` ≥ 10（与引擎运行时 `max(10, ...)` 一致）
- `proxy_cool_single_pct` ≤ 100
- `ai_interval` ≥ 60
- `ai_window` ≥ 30
- `block_page_port` 取 1~65535，且不得等于 `http_port`（否则回退默认 `7081`）；
  `block_page_redirect_ports` 仅保留合法端口（去重、按原顺序）
- `http_port` / `frp_handler_port` / `block_page_port` 三者两两不得相同
  （面板保存时直接报错；`normalize_listen` 在加载/保存时按 `7082` → `7083` 逐级回退），
  否则服务起不来或回调打到面板监听上
- `max_concurrent` / `handler_max_concurrent` 钳制到 `[8, 512]`（0/1 会让面板几乎不可用，过大失去闸门意义）
- `http_addr` 经 `/api/config` 修改时只接受 `127.0.0.1` / `0.0.0.0` / `::1` / `::`（`localhost` 归一化）
- 整型字段一律 `max(0, int(...))`（不接受负值）

运行时兜底（即使配置被手工改小也安全）：

- `ai_timeout` 取 `max(15, ...)`（`ai.call_model`）；
- `ai_min_conns` / `ai_max_ips` 取 `max(1, ...)`、`ai_window` 取 `max(30, ...)`（`ai._collect`）；
- `ai_interval` 取 `max(60, ...)`（`ai.loop_forever`）；
- `ai_ban_seconds` 取 `max(60, ...)`（`frpwaf_main.ban_ip`；AI 内部 `int(...) or 1800`）。

### 3.11 地址解析策略与 AI 出网策略（本轮新增两键）

两键都属「安全默认值」类开关：默认取值保持**原有行为**，只在你主动收紧时生效。
两者都是用严格布尔归一化处理的（`config._strict_bool`）：接受 `true/false`、`1/0`
（含 `1.0/0.0`）与大小写不敏感的 `"true"/"false"`）字符串；写错（`null`、`"abc"`、`2`）
**回退 `DEFAULTS`**，而不是被 `bool()` 静默当成真/假——两种误判都有实害（见下）。

#### 3.11.1 `strict_addr` —— 地址解析失败时的策略

背景：frps 回调 body 里的 `content.remote_addr` 是**由客户端经 frpc 上报**的，
格式不可保证。无法解析成 IP 时，旧行为是一律放行（reason `invalid-ip-pass`）——
宁可漏封也不能把正常用户拦在外面。但这意味着「回调格式一变，黑白名单与自动封禁
全体静默失效」。

| 取值 | 行为 | `conn_log.reason` |
|---|---|---|
| `false`（默认） | 放行，但**计数**（`/api/overview` 的 `invalid_addr`）并限频告警 | `invalid-ip-pass` |
| `true` | **拒连**（fail-closed） | `invalid-ip-strict` |

适用场景：只接受本机/可信 frpc 上报、且「宁可断也不能漏」的部署可以开 `true`。
**开了之后回调格式一旦变化，所有隧道会被拒**（全部 `invalid-ip-strict`）——
先看 `invalid_addr` 是否恒为 0、再决定是否打开。

#### 3.11.2 `ai_allow_private` —— AI 接口地址策略

守护进程以 root 运行，`/api/ai/test` 会把请求体里的地址交给 `urllib`。
不校验就等于「已登录用户可让 root 访问任意地址」（`file://` 读本机文件、
`http://169.254.169.254/` 读云元数据、内网管理口探测）。校验规则（`daemon.ai_url_guard`）：

1. **只允许 `http` / `https`**，其它 scheme 一律拒绝；
2. **先解析域名再判 IP**（否则「公网域名解析到内网」直接绕过）；所有解析结果
   必须都合规，任一命中拒绝即整体拒绝；
3. **永远拒绝**（不受 `ai_allow_private` 影响）：`169.254.0.0/16`（含 `169.254.169.254`）、
   `100.100.100.200/32`（阿里云元数据，经典网络）、`fd00:ec2::254/128`（AWS IPv6 元数据），
   以及 IPv6 link-local（`fe80::/10`）、**组播**与**未指定地址**（`0.0.0.0` / `::`）；
4. 私有 / 回环 / 保留地址（`10/8`、`172.16/12`、`192.168/16`、`127/8` 等）由
   `ai_allow_private` 决定：`true`（默认）放行，`false` 拒绝。

> 为什么默认允许私有地址：官方文档推荐的 AI 网关就是 `http://127.0.0.1:3000` 这类
> 内网自建地址，一刀切禁私有等于直接废掉该功能。**不要**反过来理解成「默认不安全」：
> 真正危险的元数据/链路本地网段是硬拒的，不因开关放行。
> 校验在 `/api/config` 保存时**就做一次**（不能先存恶意地址、再走 `/api/ai/test` 绕开）；
> AI 调用失败的错误摘要也不回显响应体（只回 `HTTP xxx` 状态码），防止 SSRF 被当读数据通道。

### 3.12 监听与安全关键键速查（类型 / 默认值 / 取值范围 / 是否需重启）

下表集中本轮涉及的关键键。完整说明见前文各节。

| 键 | 类型 | 默认值 | 取值范围 | 改了要不要重启 |
|---|---|---|---|---|
| `http_addr` | str | `"127.0.0.1"` | 经 `/api/config` 只能 `127.0.0.1` / `0.0.0.0` / `::1` / `::`（`localhost` 归一化为 `127.0.0.1`）；手改 json 可写任意本机地址/通配（空值回退默认） | **不用**：保存后 `_apply_listen` 立即重绑并回传实际监听位（绑定失败回退旧地址并报错） |
| `http_port` | int | `7080` | `1~65535`，且不得等于 `frp_handler_port` / `block_page_port` | **不用**：立即重绑 |
| `frp_handler_addr` | str | `"127.0.0.1"` | 任意本机地址；空值回退默认。**`/api/config` 不接受此键** | **要**：不在运行时重绑名单里，改了 `frp_handler_addr` 必须重启服务；且需重新注入 `frps.toml` 并重启 frps |
| `frp_handler_port` | int | `7082` | `1~65535`，不得等于面板/拦截页端口（冲突时加载/保存回退 `7082` → `7083`） | **不用**：立即重绑（`frps.toml` 里的 `addr` 需重新注入 + 重启 frps 才真正生效） |
| `block_page_addr` | str | `"0.0.0.0"` | 任意本机地址/通配；空值回退默认 | **不用**：后台 `_bg_loop` 每 30 秒调 `blockpage.ensure()`，比对到地址变化即重绑 |
| `max_concurrent` | int | `96` | 钳制 `[8, 512]` | **不用**：立即重绑 |
| `handler_max_concurrent` | int | `32` | 钳制 `[8, 512]` | **不用**：立即重绑 |
| `password_changed` | bool | `false` | `true`/`false`（**不采信存储值**，按口令实值推导） | **不用**：门禁每次请求读 `config.get()` |
| `strict_addr` | bool | `false` | 可识别布尔；脏值回退 `false` | **不用**：决策路径实时读配置 |
| `ai_allow_private` | bool | `true` | 可识别布尔；脏值回退 `true` | **不用**：每次地址校验实时读配置 |

> 「不用重启」的含义是「保存后 ≤1 秒（配置缓存 TTL）生效」。其中 `http_addr` /
> `http_port` / `frp_handler_port` 这三个监听项还会**主动重绑**（秒级），不需要等缓存过期；
> `frp_handler_addr` 是唯一例外——它既不在 `/api/config` 的白名单里，也不在重绑名单里。

## 4. `ip_list` 旧库自动迁移（Bug B）

`store._connect()` 在建表后调用 `_migrate_ip_list(_conn)`：

1. 读 `sqlite_master` 里 `ip_list` 的 DDL；
2. 已是 `UNIQUE(cidr, list_type)` → 跳过；
3. 检测到旧结构（含 `cidr TEXT NOT NULL UNIQUE`）→ 执行：
   - `ALTER TABLE ip_list RENAME TO ip_list_old`；
   - 建新表（新 DDL）；
   - `INSERT OR IGNORE ... SELECT` 搬运数据；
   - 删除旧表、重建 `idx_ip_list_type`；
   - 出错则**回滚**（删新表、旧表改名回来），绝不丢表。

> 迁移已在生产库上验证：4 条旧数据完整保留。迁移是一次性、幂等、可回滚的。

## 5. 统计口径（`store.stats`）

- `total_conns`：`conn_log` 总行数。
- `today_conns` / `today_rejected` / `today_uniq_ip`：**按服务器本地时区零点**计算。
  实现用 `time.mktime((y,m,d,0,0,0,...))` 取本地零点，**不是** `ts//86400*86400`
  （那是 UTC 零点，东八区 00:00–08:00 会把昨天算进今天）。
- `black_count` / `white_count`：名单条数。
- `active_bans`：生效中的封禁条数。
