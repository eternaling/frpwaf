### 10.4 升版必读（两条硬卡点）

**① `info.json` 的 `versions` 必须等于 Tag（去掉 `v`）**

### 12.1 修的是什么

v1.5.0 上线后发现的两个叠加缺陷：

**① 失败时误报「升级完成」（严重度高，会误导用户）**

插件端 worker 的返回写成 `"msg": res.get("msg") or "升级完成"`。升级失败时 `res` 通常只有 `error` 没有 `msg`，于是回退成「升级完成」——面板显示成功、版本号却没变。

生产实况（`data/job_upgrade.json`）三个字段互相矛盾，就是这个 bug 的现场：

```json
{"done":true, "ok":false, "msg":"升级完成",
 "error":"升级失败：The read operation timed out", "ms":60000}
```

daemon 端写对了（失败回「升级失败」），**只有插件端这条路径错**，而「关于」页的一键升级走的正是插件端。

**② 下载超时余量不足（同一条链路速度波动极大）**

`_download` 默认 `timeout=60`。在阿里云生产机上对同一个包实测三次：

```
第1次 4.3s / 第2次 11.0s / 第3次 28.2s   （248830 字节）
```

速度从 58 KB/s 波动到 8.8 KB/s，60 秒对最慢那次只剩 2 倍余量。

### 12.2 怎么修的

| 文件 | 改动 |
|---|---|
| `frpwaf_main.py` | 失败时 `msg = res.get("msg") or error or "升级失败（未返回原因，请查看运行日志）"`，**绝不再回退成成功文案** |

| `app/upgrade.py` | **确定性错误不重试**：哈希不匹配、体积超限直接抛——重试不会变好，且哈希不对可能是包被换过 |

### 12.3 验证


### 12.4 为什么升版而不是重发 v1.5.0

按 §3.3 的口径，「重发同一版本」不会触发任何客户端升级——`ver_tuple(latest) > ver_tuple(current)` 为假时 `apply()` 直接返回「已是最新」。而 v1.5.0 的成品包**确实含这个 bug**（它构建于 `830af54`，修复提交 `946e8e3` 在其后），所以必须升版让用户能拿到修复。

### 12.5 教训

1. 异步任务的**失败路径文案**要专门造一次失败来验，光看代码通顺容易漏
2. daemon 端与插件端实现同一件事时容易行为漂移（一个报失败、一个报成功）——同一语义有两份实现是这类问题的温床
3. 发布包构建后，应**抽查包内关键文件是否含最新修复**，而不是只验版本号

### 13.1 为什么要发这一版

### 13.2 修了什么

**① ESA 回源 IP 被误封（主因）**

现象：所有走 HTTPS 回源的站点返回 522。查证是 AI 把 ESA 的边缘节点判成
「同源多 IP、同一段集中访问 Web 代理」，批量封了 484 条中国 IP——模型自己在
理由里写的是「**疑似**」。

四层保护（层层兜底，前一层失效后一层仍能挡）：

| 层 | 机制 | 说明 |
|---|---|---|
| 1 | 模型判 `cdn_origin` | 最可靠，但模型常判 `suspicious` 并自述「无法确证 CDN」 |
| 2 | 归属地/关键字（补 `esa`/`边缘安全加速`/`aliyun cdn` 等） | 回源 IP 归属地往往只写「阿里云」，不能把「阿里云」当关键字（会放行攻击者） |
| 3 | 行为特征：同一 IP 混访 2+ 个站点代理 | 回源的本质特征 |
| 4 | **自动学习**：判过回源的 IP 记入 `trusted_cidr`；同段学到第 2 个即升级为 `/24`（现行门槛已提高到**第 3 个**，见 [08](08-AI自动IP审查.md) §5.2.2） | 无需预知回源段（owner 拿不到 ESA 的 IP 列表） |
| 5 | **同段批量封禁熔断**：窗口内同 `/24` 已有 5 个被自动封禁则停止继续封 | 事故里 `61.241.14.x` 一次被封 26 个 |

**② 把自己封了（owner 在外开发）**

remote 连数据库/SSH 时客户端反复重连，会命中阈值被封。加两道豁免：

- **登录即信任**：面板登录成功即把来源 IP 记入 `trust_login_ip`（TTL 默认 24h），
  该 IP 不触发自动封禁。换网络后登录一次面板即自动续上，无需手加白名单。
- **代理豁免**：`auto_ban_exempt_proxies`，支持 `*` 通配（任意位置）。
- AI 处置侧也认登录信任（原来只查 `ai_trusted_cidrs`，所以被 AI 封的那次没挡住）。

两者都只跳过**自动封禁**，应用层准入与日志照旧。

**③ 对账不清过期条目**

`_reconcile` 原遇到 `exp <= now` 直接 `continue`，注释写「交给集合自身 timeout」。
但 `ipset` 的 per-entry timeout 只保证到点后不命中，**条目仍留在集合里**，
导致 DB 与内核长期不一致（实测 DB 482 / ipset 491）。改为无条件下发 `del`。

**④ 工具函数去重**

`_log_text` / `_strip_masked` / `_to_bool` 在 `daemon.py` 与 `frpwaf_main.py`
各写一份，随后漂移（曾出现「一边报失败、一边报成功」）。下沉到 `app/textutil.py`。
注意 `frpwaf_main.py` 走 `_app()` 需缓存模块对象（`_app()` 每次扫目录约 2.2ms）。

### 13.3 验证

### 14.2 改了什么

**① 回源判定加类型硬否决（`app/ai.py`）**

- 判定先看端口/协议类型：来源触达的代理必须**全部属于 Web 类型**才可能被认作回源，
  纯 tcp 端口直接否决，不进后续任何一层判定。
- 多站判定（`web_multi`）需 `ptypes` 非空且全为 Web 类型，仅凭「代理名个数」不再足够。
- 弱证据不再持久化：只有 `keyword` 与「`model` 配合交叉证据」写入学习表；
  行为层单独命中与同段熔断只跳过本次。
- `category=cdn_origin` 需配合关键字命中或「全 Web 类型 + 多站点」。原实现把模型层
  当作最可靠来源，但它实际只在模型自相矛盾时才触发，属最不可靠的样本。
- 关键字收紧：删除裸 `esa`（子串会误中 `Empresa` / `Mesa` / `Telesat` / `Teresa`），
  改完整短语；4 字符以下 ASCII 关键字统一要求词边界。
- 学习条目记录命中层与来源（`model` / `keyword` / `behavior`），面板可区分。

存储侧配套（`app/store.py`）：`trusted_cidr` 增 `source` / `expires_at` / `first_reason`
三列，幂等迁移（`PRAGMA` 查列，缺列才 `ALTER`）；按来源分级有效期
（`manual` 永久 / `keyword` 30d / `model` 14d / `behavior`+subnet 24h）；
查询过滤过期、命中续期（上限 `created_at+90d`）；`purge_expired_trusted_cidrs`
挂到守护进程周期任务；条数上限淘汰；`first_reason` 冲突不覆盖，原始理由可追溯。

**② 自动处置四条路径接上可信回源网段豁免（`app/engine.py`）**

此前只有 AI 侧不处置回源来源，引擎侧的自动处置完全不查可信网段，于是
「AI 不管」形同虚设。本版让引擎侧与 AI 侧同口径，四条路径分别是：
基础阈值（第 5 步）、敏感端口探测（永久名单判定点）、CC（默认 300/60s，
共享回源节点很容易达标）、多源探测（回源节点访问多站点正是误判画像）。

- 新增 `_in_trusted_cidr()`：人工 `ai_trusted_cidrs` + 学习表，与
  `app/ai.py::_in_trusted_cidr` **同口径，两处必须一起改**。
- 新增 `_trusted_cidr_index()`：`/32` 走 `(版本, 整数)` 集合 O(1) 命中，
  宽网段（`/24` 升级）逐个比较；3 秒缓存，`invalidate_cache()` 立即失效，
  决策热路径不查库；带版本判断，避免 IPv4 `0.0.0.1` 与 IPv6 `::1` 整数相同误配。
- 读库失败按「没有可信网段」处理，宁可照常处置也不全量放行。
- 热路径开销实测：空表 4.3us/次，满载 2020 条 8.4us/次（增量约 4us）。

**③ 启动时清理旧版本遗留的误学条目**

旧口径判回源不看 `proxy_type`，「碰过 ≥2 个代理」就写成可信回源段，纯 tcp 来源
也会被记进去。这类条目（`source=legacy`）被引擎与 AI 两处同时认账，等于给一个按
现行口径根本不算回源的来源长期免处置。启动迁移 `_migrate_trusted_cidr()` 全量删除
`source='legacy'`（幂等）；新增 `store.purge_legacy_trusted_cidrs()` 只清 `legacy`，
保留 `keyword` / `model` / `manual` 等强证据。类型硬否决上线后不可能再产生
`legacy`，全删安全。

**④ 同段整段信任的升级门槛 2 → 3（`app/ai.py`）**

同 `/24` 的强证据 `/32` 达到门槛即把整段记为可信（24h 有效期）。门槛原为 2，而
模型层旁证允许「全 Web 类型 + ≥2 个代理名」，一个多站探测的 Web 来源就能占一个
强证据名额；同段凑两个即整段信任 24 小时，代价太低。提到 3 后，
「一次误判 + 邻近误判」需要连续三次才成立。

不改「必须至少一条 `keyword`」的原因：v1.5.2 那次事故的根因正是回源来源的归属地

### 15.1 为什么要发这一版

v1.5.3 之后 `main` 上又合入 11 个提交，其中包含概览指标口径改造、概览排版修复、
一套全新的系统端口防护模块与它的设置页 UI，以及一处会让面板保存完全无反应的声明
缺失修复，但都没有随之发版。

本版与前几版的性质不同：紧迫性不在「版本落后」，而在**功能丢失**。
`app/sysdetect.py` 是**全新文件**，v1.5.3 的发布包里根本没有它，换机器安装或走
「在线升级」装回来的包不含这个文件，系统端口防护这一整块能力会直接不存在；
前几版只是「装回旧行为」，本版不发的代价是「装完少一个模块」。另有一处
「保存策略」静默失效的修复也只能随包下发，无法运行期热修。

### 15.2 改了什么

**① 概览口径改造（两端，`app/store.py` / `app/firewall.py`）**

卡片此前有三处「读出来的数字不成立」：

- **连接数**：原主值是「日志窗口内的连接数」，受连接日志保留行数裁剪，日志装满后
  不再增长（线上曾出现 50001 与上限 50000 几乎相等的读数）。改为主值
  **近 24 小时连接数**（滑动窗口，不随裁剪饱和）、副行**真累计**
  （取 `sqlite_sequence.seq`，只增不减、删行与库整理都不回退，含已被裁剪的历史条目
  与被拒绝的连接，是唯一零迁移的「真累计」口径）。`total_conns` 等旧字段全部保留，
  只增不改，老前端与第三方脚本不受影响。
- **封禁卡**：原卡片把「永久名单条目数 + 临时封禁数」相加当成「当前生效」展示，
  而黑名单条目只增不减（线上 499 条），等于同一个数字换个名字继续冒充当下威胁规模。
  改为状态型：主值**近 24 小时新增封禁**（临时封禁写入 + 名单写入各计一条），
  副行**黑名单 N 条 · 临时封禁 M 条生效**，并写明「N 是名单规模，不等于生效封禁数，
  真正生效中的封禁只看『生效封禁』卡片」。
- **内核层已丢弃**：新增卡片，展示内核链累计丢弃包数与字节数（IPv4 + IPv6 合计，
  取精确计数），副行为**近 1 分钟速率**。速率采样遇计数回退（规则重建、链被清空、
  集合丢失修复等使累计归零的场景）时丢弃旧样本、以本次为新基线并显示 `—`，
  绝不返回负数；拦截页模式（REDIRECT）下不产生 DROP 计数，静默为 0 并在文案标注模式。

**② 概览排版修复（两端）**

统计口径说明原先被拼进卡片网格容器，且带的是 flex 属性（在 grid 容器内无效），
于是落进 `auto-fit` 的最窄一列、被压成逐字竖排，并把同行卡片高度从 117px 撑到 524px。
现在说明移出网格、在卡片区**之后整宽展示**（复用既有样式，零新增 CSS 类）；
卡片最小列宽 130px → 170px，1200px 左右视口不再挤成 8 列。两端副行口径也同步修正。

**③ 按来源归因（`app/firewall.py`）**

- 集合创建时启用 `counters`，即可读到每个被拦来源的命中包数与字节数；归因接口带
  10 秒缓存，面板放在「内核封禁」页折叠块，不占概览版面，读不到时显示「未启用」。
- `ipset` 无法给已存在集合补加 `counters`（`create -exist` 静默忽略），故存量集合需
  **一次性重建迁移**：先建带 counters 的**临时集合**并一次性填满当前要下发的成员，
  再按「先摘 nat、最后摘 DROP，挂回时 DROP 最先挂」的顺序销毁旧集合并改名顶上。
  切换窗口只有几条命令、**毫秒级**，其间应用层仍按数据库状态拒绝，防护不中断。
  任一步失败自动兜底：重建集合并按数据库快照**全量回填**成员、重挂规则；
  内核/`ipset` 版本不支持 counters 时保持旧格式并记日志，拦截能力不受影响。
- 迁移只在审计轮（启动首轮与每 600 秒）执行，不进 10 秒级稳态同步路径，
  「稳态零外部调用」的前提继续成立。
- 成员解析改为 token 键值解析，兼容 `ipset save` / `ipset list` 且**有/无 counters**
  两种输出格式；对账只比对 timeout，审计不会清计数。

**④ 系统端口防护（新增 `app/sysdetect.py`）**

`22` 等系统端口不过 frps 回调，既不进连接日志、也不经过准入决策，WAF 对它们完全
不可见；而内核封禁按来源 IP **不限端口**丢包。也就是说「拦住某个来源对 22 端口的
尝试」在机制上早已具备，缺的只是**检测**。本模块补这一层，**不改封禁链路与决策路径**。

- **SSH 登录成功写入登录信任（安全前提）**：原实现只有「面板登录成功」与「进入插件端
  某页」两处写登录信任，**没有任何 SSH 登录路径会写**，而内核 DROP 是全端口的——
  误封后连 22 端口都进不去。现在认证通过（公钥 / 密码 / keyboard-interactive）即写入；
  失败类事件（认证失败、无效用户、连接中断、认证次数超限）只计数，**永不写信任**。
  该开关默认开启且**不依赖检测开关**（安全前提，检测关闭时仍生效）。
- **认证日志增量检测**：按「inode + 读偏移」增量读取（默认自动探测常见路径，可配置）。
  轮转与截断都能识别并从头重读、记一条运行日志，不漏不重；**首次启动定位到文件末尾，
  历史行一律不计数**（否则开服瞬间就把过去几天算成一次批量封禁），检测关闭期间同样
  只把位置推到末尾，再次开启不补算历史；单轮有行数与字节上限，半行不消费，
  来源地址先做合法性校验。
- **默认关闭、默认只观察**：`sys_detect_enabled` 默认 `false`（内核 DROP 是全端口的，
  误封会把管理者锁在门外，必须显式开启）；`sys_detect_dry_run` 默认 `true`
  （只记录不处置，面板关闭它需二次确认并写审计）。处置走**临时封禁**（带 TTL，
  到期自动解除，进程异常退出后内核条目也按 timeout 消失），不自动升永久名单，
  单条时长有上限。
- **六道豁免**（按序短路）：白名单（**无条件生效**，不跟随白名单开关，否则会出现
  「已加白名单仍被拦」）→ 登录信任 → 可信回源段（人工 + 自动学习）→ 人工保护名单
  `sys_protect_ips` → 活跃 SSH 会话 → 非公网来源。另有**全局熔断**：每小时处置次数
  超上限即停止处置（应对整段被批量探测的连带误伤），`0` 表示不熔断。
- **观察记录独立存储**：写独立表，**不写连接日志**——连接日志会按来源聚合后送来源
  识别审查，系统端口事件没有代理名/类型，混进去既干扰判据也会让代理统计出现假条目；
  记录有保留条数上限，由后台周期任务裁剪。

**⑤ 面板（两端）**

- 设置页新增「系统端口检测」卡片（两端字段与文案一字不差）：启用开关、观察模式、
  失败次数阈值（`0` = 只计数不处置）、计数窗口、封禁时长、每小时上限、轮询间隔、
  单条封禁上限、永不封禁网段、SSH 登录写信任开关。保存只提交 `sys_*` 字段，
  合并写入、不动其它配置键。
- 设置页新增「观察记录」：时间 · 来源 · 归属地 · 命中/窗口 · 处置 · 原因，支持按来源
  与处置结果筛选与分页；顶部汇总最近 24 小时的「本应处置 / 实际处置 / 被豁免
  （按原因分组）」，汇总**不跟随筛选条件**——它要回答的是「阈值定得合不合适」。
- **修复「保存策略」静默失效（Bug AC）**：`FW_POLICY_STR` 声明在一次改动中被误删，
  而读取与保存策略仍在调用它，两个函数执行到该行即抛异常——读取时字符串字段永远
  回显为空，保存时**请求根本没发出去**，整个保存链路静默死掉。本版恢复声明、把新增
  字符串字段一并加入，并补回归用例钉住「声明必须存在」。

### 15.4 升级注意

1. **`log_max_rows` 不会自动跟随新默认值**：代码默认已是 200000，但配置迁移只给
   **缺失键**补默认值，文件里已存在的键不跟随。线上旧值若仍是 50000，需手工把
   `data/frpwaf.json` 的 `log_max_rows` 改为 `200000` 后重启（改大改小都安全，
   裁剪逻辑不假设任何固定上限）。
2. **`sys_*` 全部默认关闭**：`sys_detect_enabled=false` 时只是多一个空闲后台线程
   （每 5 秒一次状态检查，不读文件内容、不写库），默认行为无任何变化。唯一默认开启的
   是「SSH 登录成功写登录信任」，可用 `sys_trust_ssh_login=false` 或
   `trust_login_ttl=0` 关闭。
3. **启用前先观察**：建议先开启检测并**保持观察模式**跑几天，在观察记录里看被拦来源
   的分布与密度，再决定阈值，最后才关闭观察模式；建议同时把自己的常用出口段写入
   「永不封禁网段」。
4. **内核封禁集合的 counters 迁移在首次同步时自动完成**，无需人工干预；迁移失败有
   自动回填兜底，防护不中断。迁移后「来源计数」由「未启用」变为「已启用」。
5. **生效方式**：本次是 Python 代码改动，需**重启 `frpwaf` 服务**一次（无热加载）。
   若同时更新了 `app/` 下的代码或 `frpwaf_main.py`，**还需重启面板进程**
   （`systemctl restart bt`），否则插件端读到的是面板进程里缓存的旧模块
   （见 [02 §4](02-目录结构与安装部署.md) 与 [14 §四](14-运维注意事项与约束.md)）。
6. **无破坏性变更**：无配置项删除或改名；`stats()` 只增字段、旧字段全部保留；
   观察记录表用 `CREATE TABLE IF NOT EXISTS` 建，新旧库同一路径生效。
