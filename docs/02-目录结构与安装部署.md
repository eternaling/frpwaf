# 02 · 目录结构与安装部署

## 1. 仓库结构（= 插件包结构）

> **重要：插件包根目录 = 本仓库根目录。**
> 宝塔「上传安装」会扫描压缩包，取**同时含 `info.json` + `install.sh` 的目录**作为插件根，
> 并把该目录下的内容**原样**拷入 `/www/server/panel/plugin/frpwaf/`。
> 因此压缩包**根目录下必须直接包含** `app/`、`web/`、`frpwaf_main.py`、`info.json` 等，
> **不能再多套一层文件夹**。

```
/opt/frpwaf/                        项目源码 & 运行目录
├── app/                            运行代码包（Python 包，守护进程从这里启动）
│   ├── __init__.py                 版本号 __version__
│   ├── config.py                   配置读写（data/frpwaf.json）
│   ├── store.py                    SQLite 存储层
│   ├── engine.py                   准入决策引擎
│   ├── firewall.py                 内核级封禁同步（ipset + iptables）
│   ├── frp.py                      frp 服务端/客户端管理
│   ├── frp_uninstall.py             精确移除 frps.toml 中的 frpwaf 回调块
│   ├── toml_lite.py                TOML 解析/生成（纯标准库，供 frp 配置读写）
│   ├── ai.py                       AI 自动 IP 审查
│   ├── geo.py                      IP 归属地查询
│   ├── auth.py                     登录/会话（HMAC 签名 Cookie）
│   ├── job.py                      后台任务状态（提交 + 轮询、心跳、僵死判定）
│   └── daemon.py                   守护进程（回调 + 管理 API + 静态页）
├── web/
│   └── index.html                  独立管理面板（SPA）
├── data/                           运行时数据（不入库）
│   ├── frpwaf.db                   名单 / 连接日志 / 封禁 / 统计（SQLite WAL）
│   ├── frpwaf.json                 配置（含管理员密码、secret、AI 密钥）
│   ├── frpwaf.log                  运行日志
│   ├── frpwaf.pid                  PID 文件
│   ├── backup/                     数据库自动快照（frpwaf-<时间戳>.db，每 24h 一份、保留 7 份）
│   ├── frp_backup/                 frp 升级前备份（<kind>-<时间戳>/）
│   ├── frp_job.json                frp 异步安装任务进度（前端轮询）
│   ├── job_upgrade.json            在线升级任务状态（前端轮询；同类还有 job_ai_test.json）
│   ├── frp_job.log                 （预留，当前未写入）
│   └── GeoLite2-City.mmdb          （可选）归属地库，缺失时用宝塔自带的
├── frpwaf_main.py                  插件后端（宝塔 public 接口）
├── index.html                      插件前端（宝塔面板内嵌页）
├── info.json                       插件元信息（title/name/versions/checks…）
├── install.sh                      插件安装 / 卸载脚本（宝塔调用）
├── uninstall.sh                    插件卸载清理脚本
├── frpwaf.init                     服务启动脚本（安装为 /etc/init.d/frpwaf 与 /usr/bin/frpwaf）
├── frpwaf.service                  systemd unit（有 systemd 时装为 /etc/systemd/system/frpwaf.service）
├── build.sh                        组装 & 打包 & 安装插件
├── README.md                       项目说明
├── .gitignore                      git 忽略规则（data/、dist/、缓存、*.bak 等，不入库）
├── docs/                           本文档目录
└── dist/                           打包产物（build.sh 生成，不入库）
    ├── frpwaf/                     组装出的插件包（= 待上传内容）
    └── frpwaf.zip                  可直接上传宝塔的 zip
```

> `__pycache__/`、`*.pyc` 为运行时/打包产生的缓存，`build.sh` 会在打包时清理，不纳入发布包。

> `.gitignore` 明确排除 `data/`、`dist/`、`__pycache__/`、`*.db*`、`frpwaf.json/log/pid`、
> `frp_job.json`、`frp_backup/`、`*.bak.*`、`*.premigrate.*`、`*.migrate`、`*.new.*`
> ——即**运行时数据与含密钥的备份一律不入库**。

> **`data/backup/`（P2-3.11）**：守护进程每 24 小时把 `frpwaf.db` 热备成
> `frpwaf-YYYYMMDD-HHMMSS-ffffff.db`，按文件名排序保留最近 **7** 份，权限 `0600`；
> 剩余空间 < 200MB 时跳过本次并在 `/api/metrics` 的 `db_backup_fail` 计数。
> **它只含库（名单/封禁/日志），不含 `frpwaf.json` 配置**；手工恢复步骤见
> [11 §3](11-开发运维与常见问题.md)。

### 安装位置

| 位置 | 说明 |
|---|---|
| `/opt/frpwaf` | 项目源码 & **运行目录**（数据、日志、PID 都在这里） |
| `/www/server/panel/plugin/frpwaf` | 宝塔插件安装位置（`build.sh install` / 上传安装生成） |
| `/etc/init.d/frpwaf` | init 脚本（`frpwaf.init` 安装而来，**始终安装**，兼作 `frpwaf` 命令入口） |
| `/usr/bin/frpwaf` | `/etc/init.d/frpwaf` 的副本（不是软链），供任意 PATH 下直接执行 `frpwaf start` |
| `/etc/systemd/system/frpwaf.service` | systemd unit（`frpwaf.service` 安装而来，**仅在系统有 systemd 时安装**） |

> **服务托管双轨**：`frpwaf.init` 与 `frpwaf.service` **同时存在**，但只有一个是「管理者」。
> 有 systemd 时装 unit 并 `systemctl enable`，此后 init 的子命令会**转调 systemctl**；
> 没有 systemd（或插件包缺 unit）时回退 init.d + `chkconfig`/`update-rc.d`。
> 判定与切换见 §3.1。

> `app/` 与 `web/` 同时存在于**插件目录**和 `/opt/frpwaf`：安装时由插件目录同步到 `/opt/frpwaf`。
> 守护进程从 `/opt/frpwaf` 启动；插件后端优先从 `/opt/frpwaf/app` 加载代码（未部署时回退插件目录）。

## 2. 打包与上传安装

### 方式一：生成 zip 后「上传安装」（推荐给新机器）

```bash
cd /opt/frpwaf
bash build.sh zip
# -> /opt/frpwaf/dist/frpwaf.zip  （zip 根目录下就是 app/ web/ info.json …）
```

宝塔面板 → **软件商店 → 第三方插件 → 上传安装**，选择 `dist/frpwaf.zip`。

`build.sh zip` 会：
1. 把仓库根目录的 `app/ web/ frpwaf_main.py index.html info.json install.sh uninstall.sh
   frpwaf.init `**`frpwaf.service`**` 拷贝到 `dist/frpwaf/`（unit 与 init 脚本一起带上）；
2. 清理 `__pycache__`、`*.pyc`、`.DS_Store`，避免把缓存打进包；
3. **行尾归一化为 LF**（含 `*.service`）：仓库索引是 LF，但 Windows 工作区
   （`core.autocrlf=true`）检出为 CRLF，而打包是 `cp -a` 直拷工作区。unit 文件带 CRLF
   会让 systemd 把 `Restart=always\r` 判为非法值、整个 unit 解析失败（见
   [12 §Bug T](12-Bug修复记录.md)）；打包末尾还会校验「包内不得残留 CR」,
   残留则**中止打包**、绝不产出 CRLF 包；
4. 以**包内文件为顶层**打成 zip（不含 `frpwaf/` 外壳），使宝塔能直接识别。

### 方式二：本机直接安装 / 更新

```bash
cd /opt/frpwaf
bash build.sh install
```

`build.sh install` 会：
1. 组装到 `dist/frpwaf/`；
2. 拷入 `/www/server/panel/plugin/frpwaf/`，收紧权限（`.py`/`.json`/`index.html` 置 600）；
3. 清理插件目录 `__pycache__`，`touch frpwaf_main.py` 刷新 mtime 促使面板重载；
4. 写面板重载标记 `/www/server/panel/data/frpwaf.pl`；
5. 执行 `install.sh install`。

## 3. install.sh 做了什么

`install.sh` 按第一个参数显式分派：`install` → 安装，`uninstall` → 卸载，
**其它任何值（含不传参数）→ 打印用法并退出，不执行任何操作**
（由宝塔在安装/卸载时分别以 `install` / `uninstall` 调用）。

> ⚠️ 注意：**直接 `bash install.sh`（不带参数）不再执行卸载**（历史行为是默认卸载，
> 因存在误执行移除回调配置的风险，已改为显式分派）。要安装务必显式写
> `bash install.sh install`（`build.sh install` 即这么调用）；卸载用
> `bash install.sh uninstall` 或直接运行 `uninstall.sh`。

**安装（`Install_frpwaf`）：**

1. `checkos`：识别 CentOS / Debian / Ubuntu，其它系统报错退出。
2. **校验**插件目录下存在 `app/daemon.py`，否则提示「压缩包结构不对」并退出（防止残缺安装）。
3. `mkdir -p ${WAF_HOME}/data`（默认即 `/opt/frpwaf/data`）。
4. 把代码同步到 `/opt/frpwaf`：
   - 首次（`/opt/frpwaf/app/daemon.py` 不存在）：`cp -a 插件/app /opt/frpwaf/`、`cp -a 插件/web /opt/frpwaf/`；
   - 已存在（更新）：`cp -a 插件/app/. /opt/frpwaf/app/`、`cp -a 插件/web/. /opt/frpwaf/web/`（保留 `data/`）。
5. **校验**同步后 `/opt/frpwaf/app/__init__.py` 存在，否则报错退出。
6. **首次安装写配置**：`data/frpwaf.json` 不存在时写入最小配置
   （`http_addr=127.0.0.1` / `http_port=7080` / `frp_handler_addr=127.0.0.1` /
   `frp_handler_port=7082` / `password_changed=false`，`chmod 600`）；**已存在则不覆盖**，
   避免升级抹掉用户改过的监听地址 / 口令 / 名单。
7. 安装 init 脚本：`cp -f frpwaf.init /etc/init.d/frpwaf`，`tr -d '\r'` 兜底去 CR，
   `chmod +x`，再复制一份到 `/usr/bin/frpwaf`（同样去 CR + 可执行）。
8. **停掉现有实例**：`${INIT} stop`（忽略失败）。从旧 init.d/nohup 迁到 systemd 时，
   旧进程占着回调端口，不清掉会让新 unit 反复 `EADDRINUSE` 启动失败（`Restart=always` 会一直重试）。
9. **选服务托管方式**（判定逻辑见 §3.1）：
   - 有 systemd（`[ -d /run/systemd/system ]` 且 `systemctl` 可用）且能装上 unit：
     `systemctl daemon-reload` → `systemctl enable frpwaf` → `${INIT} start`
     （此时 init 检测到 unit 已启用，会转调 `systemctl start`，避免双管理互相打架）；
   - 否则回退 init.d：CentOS 用 `chkconfig --add/--level 2345 on`，其它用
     `update-rc.d frpwaf defaults`，然后 `${INIT} restart`。
10. 任一启动方式失败即 `exit 1` 并提示查看 `journalctl -u frpwaf`（systemd）或
    `/opt/frpwaf/data/frpwaf.log`（init.d）。

**卸载（`Uninstall_frpwaf`）：**

1. 委托同目录 `uninstall.sh`：由 `app/frp_uninstall.py` 精确移除回调块，
   备份原配置并校验，重启运行中的 frps；
2. 确认前置步骤成功后才停 WAF，再清理内核封禁与服务脚本；失败时中止卸载并尝试恢复回调；
3. 删除插件目录，**保留** `/opt/frpwaf/data`；彻底删除需手动 `rm -rf /opt/frpwaf`。

> `uninstall.sh` 的服务清理顺序是**先 systemd 后 init.d**（必须在 `${INIT} stop` 之前）：
> 若 unit 文件还在且已 enable，init 脚本会转调 `systemctl`，而卸载要的是彻底移除。
> 具体为 `systemctl disable --now frpwaf` → `rm -f` unit → `systemctl daemon-reload`
> → `systemctl reset-failed`，然后再删 init 脚本并**再 reload 一次**
> （否则 systemd 的 sysv 生成器会把刚删掉的 init 脚本残留成内存里的 `frpwaf.service`，
> `systemctl is-enabled frpwaf` 会报 `generated`/rc=0，看起来像没卸干净）。

> `PLUGIN_DIR` 与 `WAF_HOME` 均由脚本自身位置 / `FRPWAF_HOME` 推导，不写死，便于改名或迁移。
> `uninstall.sh` 同样以 `PLUGIN_DIR`（脚本自身位置）定位 `frps.toml` 处理逻辑。

### 3.1 服务托管：systemd unit 与 init.d 的判定与切换

两种托管方式并存，运行期只有一种生效。

**`frpwaf.service` 关键项**（`Type=simple`，主进程 PID 即守护进程 PID，pidfile 不参与 systemd 存活判定）：

| 项 | 值 | 作用 |
|---|---|---|
| `Type` | `simple` | `ExecStart` 用 `/bin/sh -c` 把 sh 换成 python，不需要 pidfile 参与判定 |
| `ExecStart` | `/bin/sh -c '… exec "$PY" -m app.daemon >>/opt/frpwaf/data/frpwaf.log 2>&1'` | 面板自带 python 优先、缺失回退 `python3`；日志**追加写文件而非 journal**（CentOS 7 的 systemd 219 不支持 `StandardOutput=append:`） |
| `After` / `Wants` | `network-online.target` | 等网络就绪：daemon 起来后立刻要监听回调端口，过早启动会与 frps 抢时序 |
| `Restart` / `RestartSec` | `always` / `2` | OOM、异常退出后 2 秒自愈，**替代 cron 看护** |
| `LimitNOFILE` | `8192` | 与 init 脚本的 `ulimit -n 8192` 对齐（每连接一线程 = 一个 fd） |
| `KillMode` / `TimeoutStopSec` | `mixed` / `15` | 先给主进程 TERM（走 `finally` 记日志），超时后对整个 cgroup KILL，避免残留子线程 |
| `WantedBy` | `multi-user.target` | 开机自启 |

**判定「谁在管」**：`frpwaf.init` 的 `systemd_managed()` 同时满足三条才认为由 systemd 托管——
① `/run/systemd/system` 存在且 `systemctl` 可用；② `/etc/systemd/system/frpwaf.service` 存在；
③ `systemctl is-enabled` 或 `is-active` 为真。命中时 `start` / `stop` / `status`
**全部转调 systemctl**，否则 `frpwaf stop` 杀掉进程会被 `Restart=always` 立刻拉回，表现为「停不掉」。

**切换到 systemd（旧 init.d 机器升级）**：`install.sh` 会自动完成（装 unit + enable），
但**必须注意 systemd 缓存旧状态**这个坑：

```bash
# systemd 可能仍记着旧 sysv 脚本的状态（Active: active (exited)，带旧时间戳），
# 此时 systemctl start 会「静默不执行」，journalctl -u frpwaf 显示 -- No entries --
# 正确做法（三步缺一不可）：
systemctl stop frpwaf && systemctl reset-failed frpwaf && systemctl start frpwaf
```

**回退到 init.d**：必须先解除 systemd 托管再删 unit，否则 `Restart=always` 会与手工启动打架：

```bash
systemctl disable --now frpwaf     # disable 自启 + 停服务
rm -f /etc/systemd/system/frpwaf.service
systemctl daemon-reload && systemctl reset-failed frpwaf
/etc/init.d/frpwaf start           # 此后 init 脚本不再转调 systemctl
```

> **unit 文件必须是 LF 行尾**：带 CRLF 时 systemd 不会忽略行尾的 `\r`，会把 `always\r`
> 判为非法值，整个 unit 解析失败。仓库已用 `.gitattributes` 的 `*.service text eol=lf`
> 固化，`build.sh` 打包归一化 + 残留 CR 即中止，`install.sh` 写入前另有 `tr -d '\r'` 兜底
> （见 [12 §Bug T](12-Bug修复记录.md)）。

**服务控制命令对照**：

| 目的 | systemd 托管 | init.d 托管 |
|---|---|---|
| 启停 | `systemctl start/stop frpwaf` | `/etc/init.d/frpwaf start/stop` |
| 两者通用 | `frpwaf start\|stop\|restart\|status`（自动按托管方式转调） | 同左 |
| 看日志 | `journalctl -u frpwaf`（多数情况下为空，因为日志重定向到了文件） | `/opt/frpwaf/data/frpwaf.log` |
| 真实日志位置 | `/opt/frpwaf/data/frpwaf.log`（两种方式一致） | 同左 |

## 4. 升级（在已有安装上更新代码）

有两种方式，效果一致（覆盖 `app/`、`web/`，保留 `data/`）：

1. **面板内**：宝塔插件页点「安装 / 更新网页端」按钮（`frpwaf_main.install_waf`）——
   把插件目录的 `app/`、`web/` 同步到 `/opt/frpwaf`，重装 init，`restart` 服务（用 `restart` 而非 `start`，
   确保加载新代码），再同步内核封禁。
2. **命令行**：`bash build.sh install`。

> 升级只替换二进制/代码，**不动** `data/` 里的配置、数据库、名单与封禁。
>
> **只有走 `install.sh` 的升级路径才会装 systemd unit**：宝塔「上传安装」与
> `bash build.sh install` 都调 `install.sh`，会把 unit 装上并 `enable`（从旧版只有 init.d 的
> 机器升上来时会自动切到 systemd）；而面板内的「安装 / 更新网页端」按钮
> （`frpwaf_main.install_waf`）**只重写 init 脚本 + `restart`，不装 unit**——
> 想切换托管方式请走 `install.sh`。
> 若插件包里缺 `frpwaf.service`（旧版 `build.sh` 不拷它），会**回退 init.d 而不是报错退出**
> ——否则一次升级就会把服务直接置为停止。

## 5. 卸载

- **宝塔面板**：插件列表「卸载」→ 触发 `uninstall.sh`（清理服务、内核规则、frps 回调注入、插件目录）。
- **命令行**：`bash install.sh uninstall`，或直接运行 `uninstall.sh`。

> 卸载后 `/opt/frpwaf/data` 仍在；如需彻底清除：`rm -rf /opt/frpwaf`。

## 6. 卸载/停用时的 fail-closed 注意

frp 的 `httpPlugins` 是 **fail-closed**：只要 `frps.toml` 里还留着指向 WAF 回调端（默认 `127.0.0.1:7082`，旧配置为 `7080`）的配置，
而 WAF 进程没在跑，frps 会**拒绝所有用户连接**。

因此卸载/停用顺序必须是：**先移除 frps 的 `[[httpPlugins]]` 回调配置并重启 frps**，再停 WAF。
本项目在 `uninstall_waf()`、`uninstall.sh` 中已按此顺序处理；前置校验或
frps 重启失败时不停止 WAF，WAF 停止失败时尝试恢复回调（见
[14-运维注意事项与约束.md](14-运维注意事项与约束.md)）。

## 7. 环境变量与路径推导

| 变量 | 默认 | 作用 |
|---|---|---|
| `FRPWAF_HOME` | `/opt/frpwaf` | 运行目录（`data/` 在其下）；用于隔离/迁移 |
| `BASH_SOURCE` | —— | `install.sh`/`uninstall.sh` 由**脚本自身位置**推导 `PLUGIN_DIR` |
| `__file__` | —— | `frpwaf_main.py` 由**自身位置**推导 `PLUGIN_DIR` |

- `app/config.py`：`BASE = os.environ.get("FRPWAF_HOME", "/opt/frpwaf")`；
  `DATA_DIR/DB_PATH/CONF_PATH/LOG_PATH/PID_PATH` 均由此推导。
- `app/frp.py`：`BACKUP_DIR`/`JOB_FILE`/`JOB_LOG` 由 `config.DATA_DIR` 推导。
- `app/geo.py`：归属地库候选路径含 `os.path.join(config.DATA_DIR, "GeoLite2-City.mmdb")`。
- `install.sh` / `uninstall.sh`：`WAF_HOME="${FRPWAF_HOME:-/opt/frpwaf}"`；`PLUGIN_DIR` 由脚本位置推导。
- `frpwaf_main.py`：`WAF_HOME = "/opt/frpwaf"`（**写死**，插件端读写 `data/frpwaf.json` 与同步代码都以此为准）。
- `frpwaf.init`：`HOME_DIR=${FRPWAF_HOME:-/opt/frpwaf}`（可用环境变量覆盖，未设则 `/opt/frpwaf`）。
- `frpwaf.service`：`WorkingDirectory` / `ExecStart` / 日志路径均写 `/opt/frpwaf`（unit 文件里无法写条件语句）；
  `install.sh` 的 `Install_systemd_unit()` 在 `WAF_HOME != /opt/frpwaf` 时**逐字串替换**后再写入 `/etc/systemd/system`。

> 结论：**改运行目录需同时设置 `FRPWAF_HOME`（供 init 脚本与 config.py）并修改
> `frpwaf_main.py` 的 `WAF_HOME`**；systemd 托管时 unit 里的路径由 `install.sh` 按 `WAF_HOME` 自动替换，
> 但替换是**逐字面量匹配 `/opt/frpwaf`**，自定义目录里若再出现该字符串会一并被换掉，需人工复核。
> 只改环境变量不会影响插件端（它把 `WAF_HOME` 写死）。
