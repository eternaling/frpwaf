# 02 · 目录结构与安装部署

## 1. 仓库结构（= 插件包结构）

> **重要：插件包根目录 = 本仓库根目录。**
> 宝塔「上传安装」会扫描压缩包，取**同时含 `info.json` + `install.sh` 的目录**作为插件根，
> 并把该目录下的内容**原样**拷入 `/www/server/panel/plugin/frpwaf/`。
> 因此压缩包**根目录下必须直接包含** `app/`、`web/`、`frpwaf_main.py`、`info.json` 等，
> **不能再多套一层文件夹**。

```
/opt/frpwaf/                        项目源码 & 运行目录
├── app/                            运行代码包（Python 包，守护进程从这里启动）
│   ├── __init__.py                 版本号 __version__
│   ├── config.py                   配置读写（data/frpwaf.json）
│   ├── store.py                    SQLite 存储层
│   ├── engine.py                   准入决策引擎
│   ├── firewall.py                 内核级封禁同步（ipset + iptables）
│   ├── frp.py                      frp 服务端/客户端管理
│   ├── toml_lite.py                TOML 解析/生成（纯标准库，供 frp 配置读写）
│   ├── ai.py                       AI 自动 IP 审查
│   ├── geo.py                      IP 归属地查询
│   ├── auth.py                     登录/会话（HMAC 签名 Cookie）
│   └── daemon.py                   守护进程（回调 + 管理 API + 静态页）
├── web/
│   └── index.html                  独立管理面板（SPA）
├── data/                           运行时数据（不入库）
│   ├── frpwaf.db                   名单 / 连接日志 / 封禁 / 统计（SQLite WAL）
│   ├── frpwaf.json                 配置（含管理员密码、secret、AI 密钥）
│   ├── frpwaf.log                  运行日志
│   ├── frpwaf.pid                  PID 文件
│   ├── frp_backup/                 frp 升级前备份（<kind>-<时间戳>/）
│   ├── frp_job.json                frp 异步安装任务进度（前端轮询）
│   ├── frp_job.log                 （预留，当前未写入）
│   └── GeoLite2-City.mmdb          （可选）归属地库，缺失时用宝塔自带的
├── frpwaf_main.py                  插件后端（宝塔 public 接口）
├── index.html                      插件前端（宝塔面板内嵌页）
├── info.json                       插件元信息（title/name/versions/checks…）
├── install.sh                      插件安装 / 卸载脚本（宝塔调用）
├── uninstall.sh                    插件卸载清理脚本
├── frpwaf.init                     服务启动脚本（安装为 /etc/init.d/frpwaf）
├── build.sh                        组装 & 打包 & 安装插件
├── README.md                       项目说明
├── .gitignore                      git 忽略规则（data/、dist/、缓存、*.bak 等，不入库）
├── docs/                           本文档目录
└── dist/                           打包产物（build.sh 生成，不入库）
    ├── frpwaf/                     组装出的插件包（= 待上传内容）
    └── frpwaf.zip                  可直接上传宝塔的 zip
```

> `__pycache__/`、`*.pyc` 为运行时/打包产生的缓存，`build.sh` 会在打包时清理，不纳入发布包。
> `.gitignore` 明确排除 `data/`、`dist/`、`__pycache__/`、`*.db*`、`frpwaf.json/log/pid`、
> `frp_job.json`、`frp_backup/`、`*.bak.*`、`*.premigrate.*`、`*.migrate`、`*.new.*`
> ——即**运行时数据与含密钥的备份一律不入库**。

### 安装位置

| 位置 | 说明 |
|---|---|
| `/opt/frpwaf` | 项目源码 & **运行目录**（数据、日志、PID 都在这里） |
| `/www/server/panel/plugin/frpwaf` | 宝塔插件安装位置（`build.sh install` / 上传安装生成） |
| `/etc/init.d/frpwaf` | 服务脚本（`frpwaf.init` 安装而来） |
| `/usr/bin/frpwaf` | 指向 `/etc/init.d/frpwaf` 的软链 |

> `app/` 与 `web/` 同时存在于**插件目录**和 `/opt/frpwaf`：安装时由插件目录同步到 `/opt/frpwaf`。
> 守护进程从 `/opt/frpwaf` 启动；插件后端优先从 `/opt/frpwaf/app` 加载代码（未部署时回退插件目录）。

## 2. 打包与上传安装

### 方式一：生成 zip 后「上传安装」（推荐给新机器）

```bash
cd /opt/frpwaf
bash build.sh zip
# -> /opt/frpwaf/dist/frpwaf.zip  （zip 根目录下就是 app/ web/ info.json …）
```

宝塔面板 → **软件商店 → 第三方插件 → 上传安装**，选择 `dist/frpwaf.zip`。

`build.sh zip` 会：
1. 把仓库根目录的 `app/ web/ frpwaf_main.py index.html info.json install.sh uninstall.sh frpwaf.init`
   拷贝到 `dist/frpwaf/`；
2. 清理 `__pycache__`、`*.pyc`、`.DS_Store`，避免把缓存打进包；
3. 以**包内文件为顶层**打成 zip（不含 `frpwaf/` 外壳），使宝塔能直接识别。

### 方式二：本机直接安装 / 更新

```bash
cd /opt/frpwaf
bash build.sh install
```

`build.sh install` 会：
1. 组装到 `dist/frpwaf/`；
2. 拷入 `/www/server/panel/plugin/frpwaf/`，收紧权限（`.py`/`.json`/`index.html` 置 600）；
3. 清理插件目录 `__pycache__`，`touch frpwaf_main.py` 刷新 mtime 促使面板重载；
4. 写面板重载标记 `/www/server/panel/data/frpwaf.pl`；
5. 执行 `install.sh install`。

## 3. install.sh 做了什么

`install.sh` 按第一个参数分派：`install` → 安装，**其它任何值（含不传参数）→ 卸载**
（由宝塔在安装/卸载时分别以 `install` / 非 `install` 调用）。

> ⚠️ 注意：**直接 `bash install.sh`（不带参数）会执行卸载**。要安装务必显式写
> `bash install.sh install`（`build.sh install` 即这么调用）。

**安装（`Install_frpwaf`）：**

1. `checkos`：识别 CentOS / Debian / Ubuntu，其它系统报错退出。
2. **校验**插件目录下存在 `app/daemon.py`，否则提示「压缩包结构不对」并退出（防止残缺安装）。
3. `mkdir -p ${WAF_HOME}/data`（默认即 `/opt/frpwaf/data`）。
4. 把代码同步到 `/opt/frpwaf`：
   - 首次（`/opt/frpwaf/app/daemon.py` 不存在）：`cp -a 插件/app /opt/frpwaf/`、`cp -a 插件/web /opt/frpwaf/`；
   - 已存在（更新）：`cp -a 插件/app/. /opt/frpwaf/app/`、`cp -a 插件/web/. /opt/frpwaf/web/`（保留 `data/`）。
5. **校验**同步后 `/opt/frpwaf/app/__init__.py` 存在，否则报错退出。
6. 安装 init 脚本：`cp -f frpwaf.init /etc/init.d/frpwaf`，`chmod +x`，软链 `/usr/bin/frpwaf`。
7. 开机自启：CentOS 用 `chkconfig`，其它用 `update-rc.d frpwaf defaults`。
8. `${INIT} restart` 启动/重启服务。

**卸载（`Uninstall_frpwaf`）：**

1. 停服务；
2. 清理内核封禁：`iptables/ip6tables` 删除 `FRPWAF_BLOCK` 链、`ipset destroy frpwaf_block(_6)`；
3. 若 `frps.toml` 含 `frpwaf`，调用同目录 `uninstall.sh` 移除回调配置并重启 frps（避免 fail-closed 残留）；
4. 取消开机自启、删除 init 脚本与 `/usr/bin/frpwaf`；
5. `rm -rf` 插件目录；
6. **保留** `/opt/frpwaf/data`（数据），彻底删除需手动 `rm -rf /opt/frpwaf`。

> `PLUGIN_DIR` 与 `WAF_HOME` 均由脚本自身位置 / `FRPWAF_HOME` 推导，不写死，便于改名或迁移。
> `uninstall.sh` 同样以 `PLUGIN_DIR`（脚本自身位置）定位 `frps.toml` 处理逻辑。

## 4. 升级（在已有安装上更新代码）

有两种方式，效果一致（覆盖 `app/`、`web/`，保留 `data/`）：

1. **面板内**：宝塔插件页点「安装 / 更新网页端」按钮（`frpwaf_main.install_waf`）——
   把插件目录的 `app/`、`web/` 同步到 `/opt/frpwaf`，重装 init，`restart` 服务（用 `restart` 而非 `start`，
   确保加载新代码），再同步内核封禁。
2. **命令行**：`bash build.sh install`。

> 升级只替换二进制/代码，**不动** `data/` 里的配置、数据库、名单与封禁。

## 5. 卸载

- **宝塔面板**：插件列表「卸载」→ 触发 `uninstall.sh`（清理服务、内核规则、frps 回调注入、插件目录）。
- **命令行**：`bash build.sh` 生成的 `install.sh uninstall`，或直接运行 `uninstall.sh`。

> 卸载后 `/opt/frpwaf/data` 仍在；如需彻底清除：`rm -rf /opt/frpwaf`。

## 6. 卸载/停用时的 fail-closed 注意

frp 的 `httpPlugins` 是 **fail-closed**：只要 `frps.toml` 里还留着指向 7080 的回调配置，
而 WAF 进程没在跑，frps 会**拒绝所有用户连接**。

因此卸载/停用顺序必须是：**先移除 frps 的 `[[httpPlugins]]` 回调配置并重启 frps**，再停 WAF。
本项目在 `uninstall_waf()`、`uninstall.sh` 中已按此顺序处理（见
[14-运维注意事项与约束.md](14-运维注意事项与约束.md)）。

## 7. 环境变量与路径推导

| 变量 | 默认 | 作用 |
|---|---|---|
| `FRPWAF_HOME` | `/opt/frpwaf` | 运行目录（`data/` 在其下）；用于隔离/迁移 |
| `BASH_SOURCE` | —— | `install.sh`/`uninstall.sh` 由**脚本自身位置**推导 `PLUGIN_DIR` |
| `__file__` | —— | `frpwaf_main.py` 由**自身位置**推导 `PLUGIN_DIR` |

- `app/config.py`：`BASE = os.environ.get("FRPWAF_HOME", "/opt/frpwaf")`；
  `DATA_DIR/DB_PATH/CONF_PATH/LOG_PATH/PID_PATH` 均由此推导。
- `app/frp.py`：`BACKUP_DIR`/`JOB_FILE`/`JOB_LOG` 由 `config.DATA_DIR` 推导。
- `app/geo.py`：归属地库候选路径含 `os.path.join(config.DATA_DIR, "GeoLite2-City.mmdb")`。
- `install.sh` / `uninstall.sh`：`WAF_HOME="${FRPWAF_HOME:-/opt/frpwaf}"`；`PLUGIN_DIR` 由脚本位置推导。
- `frpwaf_main.py`：`WAF_HOME = "/opt/frpwaf"`（**写死**，插件端读写 `data/frpwaf.json` 与同步代码都以此为准）。
- `frpwaf.init`：`HOME_DIR=/opt/frpwaf`（**写死**，若要迁移需同时改此脚本）。

> 结论：**改运行目录需同时设置 `FRPWAF_HOME`、修改 `frpwaf.init` 的 `HOME_DIR`，并修改
> `frpwaf_main.py` 的 `WAF_HOME`**。只改环境变量不会影响 init 脚本（它是系统服务脚本，
> 不读环境变量），也不会影响插件端（它把 `WAF_HOME` 写死）。
