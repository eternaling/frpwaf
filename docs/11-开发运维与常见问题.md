# 11 · 开发运维与常见问题

## 1. 服务控制

服务脚本 `/etc/init.d/frpwaf`（软链 `/usr/bin/frpwaf`），按 **PID 文件**管理：

```bash
frpwaf start      # 启动（nohup python -m app.daemon）
frpwaf stop       # 停止（先 kill，最多等 10s，再 kill -9）
frpwaf restart    # 重启
frpwaf status     # 状态
```

- 启动命令：`cd /opt/frpwaf && nohup <python> -m app.daemon >> data/frpwaf.log 2>&1 &`
- Python：`/www/server/panel/pyenv/bin/python`，缺失时回退 `python3`。
- PID 文件：`/opt/frpwaf/data/frpwaf.pid`。

> **⚠️ 严禁使用 `pkill` / `pkill -f`** 杀进程！本项目守护进程是
> `python -m app.daemon`，`pkill -f "app.daemon"` 会误杀匹配到的**生产进程**
> （曾因此造成生产 WAF 被误杀的事故）。**只按精确 PID 终止**，或直接用
> `frpwaf stop`。

## 2. 日志

| 日志 | 位置 | 说明 |
|---|---|---|
| WAF 运行日志 | `data/frpwaf.log` | 启动/停止/拒绝连接/登录/心跳/后台异常；>2MB 截断保留尾部 1MB |
| frps 日志 | 由 frps 配置 `[log] to` 决定（默认 `/var/log/frps.log`） | **本插件不改动 frps 日志配置** |
| frp 安装任务 | `data/frp_job.json`（进度，前端轮询；`data/frp_job.log` 为预留未写入） | 异步安装 |

> **约束：不要改动 frps 的日志配置。**

## 3. 备份与恢复

- **数据备份**：直接复制 `/opt/frpwaf/data/`（`frpwaf.db` + `frpwaf.json`）。
  建议先 `store.checkpoint(truncate=True)` 或停服务，保证 WAL 已合并。
- **配置备份**：`frpwaf.json` 单独保存即可（含名单之外的策略/账号/密钥）。
- **frp 备份**：升级前 `frp.py` 自动备份到 `data/frp_backup/<kind>-<时间戳>/`，
  可 `frp_rollback` 还原。
- **恢复**：停服务 → 覆盖 `data/` → 启动。

## 4. 私有包加载机制（开发必读）

插件后端在**宝塔面板常驻进程**里运行，不能用通用包名 `app` 导入运行代码
（会与面板自身/其它插件的 `app` 包冲突）。本项目用私有包名 **`frpwaf_app`**：

- `_app_pkg_dir()`：优先 `/opt/frpwaf/app`，回退插件目录 `app/`，
  再回退 `../frpwaf/app`；都找不到抛**中文** `FileNotFoundError`。
- `_load_app_pkg()`：`importlib.util.spec_from_file_location(_APP_PKG, __init__.py,
  submodule_search_locations=[pkg_dir])` 注册私有包；被顶替时重建。
- `_app(modname)`：比对 `app/*.py` 的 **mtime 签名**，源码变更时**丢弃旧包重新导入**
  （面板常驻，否则一直跑旧代码）。

> 开发时改了 `app/*.py`，插件端会在下次调用时自动重载；但**守护进程**是独立进程，
> 需 `frpwaf restart` 才生效。Web 端与插件端共享同一份代码目录。

### 4.1 守护进程的后台线程

`daemon.main()` 启动两个后台线程：

1. **`_bg_loop()`**（每 10 秒一轮）：
   - `engine.auto_release()` 释放到期封禁（记日志）；
   - `store.trim_logs()` / `store.trim_bans(20000)` / `store.trim_ai_review()` 裁剪日志与历史；
   - `_fw_sync()` 对账内核封禁；
   - 每约 60 秒（6 轮）做一次 `checkpoint(truncate=True)` 回收 `-wal`；
   - 每约 10 分钟（60 轮）写一条心跳日志（含生效封禁数、内存占用）。
2. **`ai.loop_forever()`**（每 20 秒醒一次）：到间隔则执行一次 AI 审查（见 [08](08-AI自动IP审查.md)）。

> 两者都用 `daemon=True`（随主进程退出），异常均被捕获并记入 `frpwaf.log`，不会导致服务退出。

## 5. 打包发布

```bash
cd /opt/frpwaf
bash build.sh          # 仅组装 -> dist/frpwaf
bash build.sh zip      # 组装并打 zip -> dist/frpwaf.zip（可直接上传宝塔）
bash build.sh install  # 组装并安装到本机插件目录
```

- 插件包**根目录 = 仓库根目录**（`app/ web/ info.json install.sh ...` 直接在内），
  zip 也以**包内文件为顶层**（不含 `frpwaf/` 外壳），宝塔上传即可识别。
- 打包会清理 `__pycache__`/`*.pyc`/`.DS_Store`。
- **发布需用户明确同意**，且须先改版本号（见 [13-变更历史与版本.md](13-变更历史与版本.md)）。

## 6. 调试技巧

### 6.1 起一个隔离实例（不动生产）

用独立的 `FRPWAF_HOME` 与端口起临时实例，避免影响生产：

```bash
export FRPWAF_HOME=/tmp/frpwaf_test
mkdir -p "$FRPWAF_HOME/data"
# 写一份独立配置，改用非默认端口（避免与生产的 7080 冲突）
cat > "$FRPWAF_HOME/data/frpwaf.json" <<'JSON'
{
  "http_addr": "127.0.0.1",
  "http_port": 17080,
  "web_enabled": true,
  "admin_user": "admin",
  "admin_password": "123456",
  "fw_sync_enabled": false
}
JSON
# 从项目目录启动（代码仍来自 /opt/frpwaf/app，数据写到 FRPWAF_HOME）
cd /opt/frpwaf
FRPWAF_HOME=/tmp/frpwaf_test /www/server/panel/pyenv/bin/python -m app.daemon &
echo "隔离实例 PID=$!"
# 访问 http://127.0.0.1:17080/  （默认 admin / 123456）
```

要点：

- `FRPWAF_HOME` 决定 `data/`（DB/配置/日志/PID）位置；**不设则默认 `/opt/frpwaf`**。
- 用非默认端口（如 17080）且 `http_addr` 设 `127.0.0.1`，避免与生产冲突/暴露。
- 隔离实例默认 `fw_sync_enabled: false`，**不要**在生产机器上开内核封禁测试
  （会改写生产 ipset/iptables）。
- **关闭隔离实例时按精确 PID**：`kill $隔离实例PID`，**不要** `pkill`（会误杀生产）。

### 6.2 查看后台/调试信息

本项目**没有** `FRPWAF_DEBUG` 之类的调试开关。调试主要靠：

- `data/frpwaf.log`：启动/停止/拒绝连接/登录/心跳/后台异常（`daemon._log()`）；
- 面板「运行日志」页（插件端 `get_log` / Web 端无此页，直接看文件）；
- 前台直接跑 `python -m app.daemon`（不 nohup）可看到 stdout 的启动行
  与 `traceback.print_exc()` 打印的决策异常栈。

### 6.3 模拟 frps 回调

```bash
curl -s -X POST 'http://127.0.0.1:7080/frp/handler?op=NewUserConn' \
  -H 'Content-Type: application/json' \
  -d '{"content":{"remote_addr":"1.2.3.4:5555","proxy_name":"web","proxy_type":"tcp","user":{"user":""}}}'
# 放行: {"reject": false, "unchange": true}
# 拒绝: {"reject": true, "reject_reason": "blacklist"}
```

> 注意：`/frp/handler` 仅接受**本机来源**（127.0.0.1/::1）。从其它机器/容器网络
> 模拟回调会得到 `403 forbidden`（属预期防护），需在 WAF 所在主机上执行；
> 非本机拒绝次数可在 `/api/overview` 的 `frp_remote_denied` 字段查看。

### 6.4 检查内核集合

```bash
ipset list frpwaf_block
iptables -S FRPWAF_BLOCK
iptables -C INPUT -j FRPWAF_BLOCK && echo "已挂载"
```

## 7. 常见问题（FAQ）

### Q1：面板打不开 / 登录后又跳回登录页

- 检查服务：`frpwaf status`；端口：`ss -lntp | grep 7080`。
- 若经 HTTPS 反代，设 `X-Forwarded-Proto: https` 或 `cookie_secure=true`
  （否则 Cookie 因 `Secure` 标记不被回传——本项默认不加，见 [09](09-认证与安全.md)）。

### Q2：点击插件报 `FileNotFoundError: .../app/__init__.py`

插件包结构不对（缺少 `app/` 或**多套了一层文件夹**）。重新用 `bash build.sh zip`
生成 `dist/frpwaf.zip` 上传安装；确认压缩包**根目录**直接含 `app/`。

### Q3：frp「安装/升级」报 `ModuleNotFoundError: app.frp`

旧版本 bug。当前版本已用私有包名 `frpwaf_app` 加载修复（提交 `b8628fb`）。

### Q4：关闭了内核封禁，为什么还被拦？

旧版本关闭开关时未清理内核残留。当前版本任何关闭路径都会 `teardown()`
（Bug A，提交 `cedf595`）。若仍有残留：在插件端「IP 名单 / 封禁」页的内核封禁卡片点一次手动同步（关闭态会清理），
或手动 `iptables -D INPUT -j FRPWAF_BLOCK; ipset destroy frpwaf_block`。

### Q5：白名单 IP 却连不上

黑名单是**大段 CIDR**、白名单是其中**小 IP** 时的差集问题（Bug C）。升级到含
`_apply_whitelist` 的版本。确认「白名单」开关已开。

### Q6：改了 `frps.toml` 后 frps 起不来

新版 frp 严格解析，旧字段会 `unknown field`。用插件端「frp 管理 → 配置」保存
（自动 `verify` + 失败回滚），或升级时 `_migrate_config` 自动迁移。

### Q7：连接日志按「动作」筛选查不到数据

宝塔路由的 `action=a` 会污染 `get.action`。前端须用 **`log_action`** 参数
（代理筛选用 **`log_proxy`**）。已在代码与前端规避。

### Q8：卸载后 frps 全线拒绝连接

卸载时若未先移除 `frps.toml` 的 `[[httpPlugins]]`，frps 会一直回调已停止的 WAF
（fail-closed）。本项目 `uninstall_waf()` / `uninstall.sh` 已按「先移除回调再停 WAF」
处理。手动修复：删掉 `frps.toml` 中 `name="frpwaf"` 的块并重启 frps。

### Q9：内核封禁显示 `available=false`

需 root + 系统安装 `ipset`、`iptables`。Debian：`apt install ipset iptables`。

### Q10：归属地显示「未知」

未找到 GeoLite2 库或未装 `maxminddb`。`app/geo.py` 按顺序探测以下路径（取第一个存在的）：
`/www/server/panel/config/GeoLite2-City.mmdb`（宝塔自带）→
`/usr/share/GeoIP/GeoLite2-City.mmdb` → `data/GeoLite2-City.mmdb`。
把 mmdb 放到任一位置即可；纯离线、无网络请求。

### Q11：运行日志刷 `ConnectionResetError` traceback（已修复）

**现象**：`data/frpwaf.log` 反复出现

```
Exception occurred during processing of request from ('45.79.211.97', 58032)
... ConnectionResetError: [Errno 104] Connection reset by peer
```

**根因**：扫描器/客户端连上 7080 端口后**半途断开**（请求行还没发完就 RST），
`http.server` 的默认 `handle_error` 会把该异常完整堆栈打印到 **stderr**；
而服务脚本以 `nohup ... >>frpwaf.log 2>&1` 启动，stderr 与 stdout 合并写入运行日志。

**修复**（Bug I，`app/daemon.py`）：重写服务器 `handle_error`，
`ConnectionResetError` / `BrokenPipeError` / `TimeoutError` 等客户端断连类异常**静默**，
每 10 分钟最多汇总一行「已静默 N 条客户端断连异常」；其余异常仍打印完整堆栈。
**判读**：日志中偶尔出现该汇总行属正常（说明有人在扫 7080），无需处理；
若不再出现任何汇总行也正常（无人扫）。

### Q12：frps 日志刷 `no route found`（frp 自身行为，非 Bug）

**现象**：`/var/log/frps.log` 反复出现

```
[W] [httputil/reverseproxy.go:500] do http proxy request [host: book.nightb.cn] error: no route found: book.nightb.cn /32_32299/24.html
[W] [httputil/reverseproxy.go:500] do http proxy request [host: 47.106.172.12:80] error: no route found: 47.106.172.12 /
```

**含义**：该日志由 **frp 服务端二进制**产生（`pkg/util/vhost` 的 `CreateConnection`），
不是本插件打的。`host` 是请求携带的域名/地址，第二段是请求路径与路由用户。
出现它说明：**有人直接访问了 frps 的 HTTP 代理端口（`vhostHTTPPort`），
但其 Host 不匹配任何已注册的 http 代理域名** —— 常见于：

- 扫描器直接扫 IP:端口（`47.106.172.12 /`）；
- 探测未配置的域名（`book.nightb.cn /32_32299/24.html`）；
- 攻击者构造的路径扫描。

frp 对这类请求**返回 404 页面并记录一条 Warn**，属预期防御行为，**不影响正常业务**。

**判读与处置**（按推荐顺序）：

1. **可忽略**：日志量不大时可不管——它恰好说明 frp 正常拒绝了未知 Host。
2. **降低记录级别**：插件端「frp 管理 → 配置修改」把 `log.level` 改为 `error`
   （保存后重启 frps 生效）。注意这会同时隐藏其它 `[W]` 警告（如隧道连接失败提示）。
3. **不开无用监听**：若根本没用 HTTP 代理（无 `vhostHTTPPort` 需求），
   在 frps 配置中清空 `vhostHTTPPort` 并重启 frps，该端口不再监听，日志自然消失。
4. **限制来源**：`vhostHTTPPort` 仅应被 CDN/反代访问时，用系统防火墙限制来源 IP
   （插件端「frp 管理 → 一键放行端口」只负责放行，收紧需手动加防火墙规则）。

> ⚠️ 注意：HTTP 代理（vhost）**不会触发 `NewUserConn` 回调**（frp 的该钩子只覆盖
> `tcp`/`stcp`/`https`/`tcpmux`），因此这类扫描流量**不经过本 WAF 的决策与审计**。
> 若需要拦截它们，应在上游 CDN/反代或系统防火墙层处理，或改用 tcp 代理类型。

## 8. 代码结构速查

| 文件 | 职责 |
|---|---|
| `app/config.py` | 配置读写 + 1s 缓存 |
| `app/store.py` | SQLite（WAL）+ 自愈连接 + 旧库迁移 |

| `app/auth.py` | 会话签名 + 登录校验 |

| `web/index.html` | 独立 Web 面板 SPA |
| `index.html` | 宝塔插件内嵌页 |
