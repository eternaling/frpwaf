# 测试与验证文档（docs/tests）

本目录存放 frpwaf 的验证计划与验证报告，配合 `test-development` 技能使用。

## 目录结构

```
docs/tests/
  plans/                     # 验证计划（动手前写）
    test-{YYYYMMDD}-{主题}.md
  reports/YYYY-MM/           # 验证报告（执行后写）
    report-{YYYYMMDD}-{主题}.md
```

## 验证计划模板

```markdown
# 验证计划：{主题}

- 关联任务：{docs/tasks/active/xxx.md}
- 日期：{YYYY-MM-DD}
- 环境：{本地 Windows / 服务器宝塔}

## 验证目标

{本次要证明什么}

## 用例清单

| # | 用例 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|---|
| 1 | {用例名} | | | |

## 回归范围

- {受影响模块：决策链/缓存/面板/内核同步等}
```

## 验证报告模板

```markdown
# 验证报告：{主题}

- 关联计划：{plans/xxx.md}
- 执行日期：{YYYY-MM-DD}
- 结论：通过 / 不通过（原因）

## 执行结果

| # | 用例 | 实际结果 | 判定 |
|---|---|---|---|
| 1 | | | ✅ / ❌ |

## 遗留问题

- {未通过项与处理建议}
```

## 使用规则

1. 修改核心模块（engine / store / config / firewall / 回调）前先写计划；
2. 验证命令优先使用标准库与项目脚本（禁止引入测试框架依赖）；
3. 报告要含可复现的命令与输出摘要，禁止只写「已测试通过」；
4. 临时验证脚本放系统临时目录，不提交进仓库。
