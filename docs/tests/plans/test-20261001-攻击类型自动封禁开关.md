# 验证计划：攻击类型自动封禁开关（CC / 端口扫描 / 敏感服务爆破）

- 关联任务：docs/tasks/active/task-20261001-171000-攻击类型自动封禁开关.md
- 日期：2026-10-01
- 环境：本地 Windows（Python 3.12）+ 隔离实例（FRPWAF_HOME 临时目录）

## 验证目标

1. 三个新开关默认全部开启（用户要求开箱即用），参数为保守默认值。
2. 显式全部关闭时零行为变化（不计数、不封禁）；开启后各自按窗口/阈值触发：
   CC 与扫描写临时封禁，敏感服务写永久黑名单。
3. 白名单命中（`whitelist_enabled` 开启时）不被任何自动封禁影响。
4. 旧配置（无新键）加载不报错，自动补默认值（含默认开启）。
5. code-reviewer 审查发现项修复后的回归：
   - S1：`wordpress` 等含 `rdp` 子串的普通代理名不误判；HTTP 类代理不参与敏感服务检测。
   - M1：持续新 IP 涌入时计数字典有界（≤5000）。
   - M2：并发连接同时到达阈值只写一条封禁记录；**加固**：计数「阈值封顶 + 只认领
     一次」，封禁写入可见前的窄窗口内并发连接不会二次触发（重复运行并发用例验证稳定）。
   - M3：黑名单开关关闭时敏感服务封禁降级为临时封禁（仍被拦截）。
   - L4：写库失败时回填计数，下一次连接立即重试写入。
6. 防呆：开关开启时阈值/时长 0、窗口 ≤1 秒视为「未设置」，加载/保存自动回退默认值。
7. 迁移：旧版 0/0/0 哨兵组合一次性恢复默认开启；迁移后用户手动关闭不再被重置。
8. `python -m py_compile app/*.py frpwaf_main.py`、`node scripts/audit-agent-migration.cjs` 通过。
