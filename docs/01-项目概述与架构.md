# 01 · 项目概述与架构

## 1. 项目是什么

**FRP WAF** 是一套基于 **frp `httpPlugins`** 的 IP 准入控制防火墙，以 **宝塔面板插件** 形式安装，
并额外提供**独立管理面板**（Web SPA，监听 7080）。

它对访问 frps 代理端口的来源 IP 做：

- **黑/白名单**（支持单个 IP 与 CIDR 网段，白名单优先）
- **手动封禁 / 解封**（永久黑名单 与 临时封禁）
- **自动封禁**（按窗口内连接次数阈值）
- **限速**（单 IP 每秒新连接上限）
- **连接审计日志**（含归属地）
- **内核级封禁**（把封禁同步到 ipset + iptables，在内核层丢包）
- **AI 自动 IP 审查**（把高频来源 IP 交给大模型判定并分级处置：
  确凿→永久黑名单、疑似→临时封禁、SSH 相关从严）

同时把宝塔官方 **「frp管理器」** 插件的功能（frps/frpc 安装、升级、配置、启停）并入本插件，
并修复其若干已知问题（见 [06-frp服务端客户端管理.md](06-frp服务端客户端管理.md)）。

## 2. 解决的核心问题

| 痛点 | 本项目的做法 |
|---|---|
| frps 缺少按来源 IP 的准入控制 | 用 frp `httpPlugins` 的 `NewUserConn` 钩子做应用层准入 |
| 应用层拒绝后连接数仍疯涨、耗资源 | 把封禁下发到 **ipset + iptables**，内核层直接 DROP |
| 官方 frp管理器停更、功能残缺 | 并入其功能并修复：升级保留配置、多架构、动态版本、配置校验 |
| 手工维护黑名单繁琐 | 提供面板 + AI 自动审查 |
| 面板独立部署麻烦 | 一个守护进程同时承担「frps 回调」+「管理面板」 |

## 3. 整体架构

```
                       ┌──────────────────────────────┐
   用户/攻击者  ───────▶│  frps（代理端口 15443/80/443）│
                       └──────────────┬───────────────┘
                                      │ 每次 NewUserConn 回调
                                      ▼
                       POST http://127.0.0.1:7080/frp/handler?op=NewUserConn
                                      │
        ┌─────────────────────────────▼─────────────────────────────┐
        │              frpwaf 守护进程（python -m app.daemon）        │
        │  一个进程、一个端口（7080）同时提供：                        │
        │   1) frps 回调端   POST /frp/handler                       │
        │   2) 管理 API      /api/*（需登录）                          │
        │   3) 静态面板      /  （web/index.html）                     │
        │                                                            │
        │   决策：engine.decide()  →  allow / reject                 │
        │   存储：store（SQLite WAL）                                 │
        │   配置：config（data/frpwaf.json，1s 缓存）                  │
        │   内核：firewall（ipset+iptables 同步，后台每 10s 对账）      │
        │   审查：ai.loop_forever()（按间隔运行）                       │
        └──────────────┬───────────────────────────┬─────────────────┘
                       │ 拒绝的 IP                  │ 名单/封禁
                       ▼                           ▼
              frps 断开该连接                ipset frpwaf_block
                                            iptables FRPWAF_BLOCK → DROP
```

宝塔面板插件（`frpwaf_main.py`）作为**管理入口**，负责：安装/更新 WAF、网页端开关/换端口、
注入 frps 回调配置（移除随「卸载」进行，见 [14](14-运维注意事项与约束.md) §2.2）、frp 管理、
IP 名单与封禁操作、AI 配置等；它与守护进程共享同一份
`/opt/frpwaf/data` 配置与数据库。

## 4. 组件职责一览

| 组件 | 文件 | 职责 |
|---|---|---|
| 守护进程 | `app/daemon.py` | 单进程单端口：frps 回调 + 管理 API + 静态面板；后台对账/裁剪/心跳 |
| 配置 | `app/config.py` | 读写 `data/frpwaf.json`，带 1s 内存缓存与写后失效 |
| 存储 | `app/store.py` | SQLite（WAL）：名单、连接日志、封禁、代理统计、AI 记录 |
| 决策引擎 | `app/engine.py` | 按优先级判定 allow/reject，规则与封禁带短 TTL 缓存 |
| 内核封禁 | `app/firewall.py` | 同步名单/封禁到 ipset+iptables，白名单差集，状态查询 |
| frp 管理 | `app/frp.py` | frps/frpc 安装/升级/回滚/配置/日志/启停（含官方插件问题修复） |
| AI 审查 | `app/ai.py` | 汇总高频 IP 调用大模型判定，按判定分级处置（永久/临时） |
| 归属地 | `app/geo.py` | 读取本机 GeoLite2 mmdb，离线查询，带缓存 |
| 认证 | `app/auth.py` | HMAC 签名会话 Cookie，登录校验，改密/改账号 |
| 插件后端 | `frpwaf_main.py` | 宝塔 `public` 接口，私有包加载 `frpwaf_app`，安装/集成/管理 |
| 插件前端 | `index.html` | 宝塔面板内嵌页（概览/封禁/AI/设置/连接日志/frp 管理） |
| 独立面板 | `web/index.html` | 独立 Web SPA（登录/概览/名单/日志/封禁/查询/统计/设置） |
| 服务脚本 | `frpwaf.init` | `/etc/init.d/frpwaf`：start/stop/restart/status（按 PID 管理） |
| 安装/打包 | `install.sh` `uninstall.sh` `build.sh` | 上传安装识别、同步代码、打包 zip、本地安装 |

## 5. 技术栈与依赖

- **语言**：Python 3（宝塔面板自带 `pyenv`：`/www/server/panel/pyenv/bin/python`；
  服务脚本 `frpwaf.init` 也用它，缺失时回退 `python3`）
- **第三方依赖**：
  - ~~`toml`~~（**已移除**：frp 配置读写改用自带 `app/toml_lite.py`，纯标准库实现；
    早期版本依赖宝塔 pyenv 自带的 `toml`，环境缺失时报「缺少 toml 模块」）
  - `maxminddb`（IP 归属地，**可选**；缺失时降级为「未知」，不影响其它功能）
  - 系统命令：`ipset`、`iptables`/`ip6tables`、`ss`、`curl`、`tar`、`tail`、`zip`、
    `ps`/`kill`（frp init 脚本用）
- **无 Web 框架**：管理面板与 API 由标准库 `http.server`（`ThreadingHTTPServer`）实现
- **无 ORM**：直接使用标准库 `sqlite3`（WAL 模式）
- **AI 调用**：仅用标准库 `urllib`，无额外依赖
- **无 `requirements.txt`**：所有依赖均为「系统/宝塔自带」或「可选项」，无需 pip 安装

## 6. 数据流（一次连接）

1. 用户访问 frps 代理端口 → frps 发起 `NewUserConn` 回调到 `/frp/handler`。
2. `daemon._frp_handler()` 解析来源 `remote_addr`、`proxy_name`、`proxy_type`、`user`。
3. 调用 `engine.decide()`：
   - 白名单命中 → allow；黑名单命中 → reject；生效封禁 → reject；
   - 限速超限 → reject；自动封禁触发 → reject；否则 allow。
4. 写 `conn_log`（allow/reject + 原因）并 `bump_proxy` 统计。
5. 返回 `{"reject": false, "unchange": true}` 或 `{"reject": true, "reject_reason": ...}`。
6. 后台线程每 10s 把「黑名单 + 生效封禁」按开关与白名单差集同步到内核 ipset，
   使被禁 IP 的数据包在内核层即被 DROP（计数停止增长）。

详见 [03-工作原理与准入决策.md](03-工作原理与准入决策.md) 与 [05-内核级封禁.md](05-内核级封禁.md)。
