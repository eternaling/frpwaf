# 14 · 运维注意事项与约束

> 本文汇总本项目的**不可触碰约束**、**危险操作清单**与**fail-closed 处置**。
> 这些约定来自真实事故与明确要求，务必遵守。

## 一、不可触碰的约束（硬性）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **不要改动 frps 日志配置** | frps 的 `[log]` 段落保持原样，不修改、不迁移、不重写 |
| 2 | **不要擅自升级 frps 版本** | 升级 frps 属高危动作，**须经明确同意**后再执行 |
| 3 | **不要擅自调整面板暴露** | 面板的对外暴露/端口变更须经明确同意 |

| 5 | **不泄露真实账号密码** | 「**别在 git 漏出我真实的账号密码呀**」——配置/文档/提交中一律用占位或掩码 |

## 二、危险操作清单（⚠️）

### 2.1 严禁 `pkill` / `pkill -f`

**本项目守护进程运行命令是 `python -m app.daemon`。**

```bash
# ❌ 绝对禁止：
pkill -f "app.daemon"     # 会匹配并杀掉生产 WAF 进程（曾造成生产事故）
pkill -f frpwaf
```

**只允许按精确 PID 终止**，或使用服务脚本：

```bash
frpwaf stop               # ✅ 推荐
kill <精确PID>            # ✅ 已知 PID 时
```

> 隔离实例、临时进程同样按精确 PID 关闭。

### 2.2 停用 / 卸载顺序（fail-closed）

**必须先移除 frps 的 `[[httpPlugins]]` 回调配置并重启 frps，再停 WAF。**
顺序颠倒会导致 frps 一直回调已停止的 WAF → **fail-closed 全线拒绝用户连接**。

本项目已在 `uninstall_waf()`、`uninstall.sh` 中按此顺序实现，手动操作时务必遵守。

### 2.3 改 `frps.toml`

- 改前 `frp.py` 会自动 `cp` 备份；改后 `frps verify` 校验，失败自动回滚。
- **不要**手工删除/破坏 `[[httpPlugins]]` 以外的既有段落。
- 改完必须 `frps restart` 才生效。

### 2.4 改 `data/frpwaf.json`

- 文件含 `secret`/`admin_password`/`ai_api_key`，权限 `600`。
- 插件端 `_set_cfg` 在读取失败时**拒绝保存**，防止抹除敏感字段。
- 手工编辑务必保持合法 JSON，否则读取回退空配置。

### 2.5 内核封禁

- 关闭 `fw_sync_enabled` 会 `teardown()` 清理 iptables/ipset。
- 不要手工在 `FRPWAF_BLOCK` 链里加自定义规则（会被对账逻辑覆盖/清理）。
- `iptables -F` / `iptables -X`（不带链名）属全局危险操作，**禁止**。

## 三、fail-closed 处置手册

### 3.1 原理

frp `httpPlugins` 为 **fail-closed**：`frps.toml` 有回调配置、而 WAF 不可达 →
frps **拒绝所有**新用户连接。

### 3.2 WAF 挂了，业务全断，怎么快速恢复？

**两条路**：

**A. 尽快恢复 WAF**（保住防护）：
```bash
frpwaf status
frpwaf restart          # 或 frpwaf start
# 确认监听：ss -lntp | grep 7080
# 确认回调：curl -s -X POST 'http://127.0.0.1:7080/frp/handler?op=NewUserConn' \
#   -H 'Content-Type: application/json' -d '{"content":{"remote_addr":"127.0.0.1:1"}}'
```

**B. 临时解除（牺牲防护换可用性）**：移除回调配置并重启 frps：
```bash
# 备份
cp -a /usr/local/frps/frps.toml /usr/local/frps/frps.toml.bak.$(date +%F-%H%M%S)
# 手动删除 name="frpwaf" 的 [[httpPlugins]] 块（见下方说明），或直接运行卸载脚本
/etc/init.d/frps restart
```
> 说明：插件端**没有**「移除回调」按钮，只有「注入回调」（`apply_to_frps`）。
> 移除回调的正规途径是**卸载**（`uninstall_waf()` / `uninstall.sh`，会自动移除回调并重启
> frps），或按 [02 §3](02-目录结构与安装部署.md) / `uninstall.sh` 中的块删除逻辑手动操作。
> 恢复 WAF 后再用插件端「frps 集成 → 注入」重新挂上回调。

### 3.3 决策异常 vs 进程不可达

- **单次决策异常** → `daemon` 内 `allow=True`（fail-open），只放行本次，不影响整体；
- **进程不可达** → frps fail-closed 全拒。
  这是**有意**设计：小 bug 不炸业务，但防护进程没了就不放流量。

## 四、日常运维检查清单

- [ ] `frpwaf status` 为 running；`ss -lntp | grep 7080` 有监听；
- [ ] `data/frpwaf.log` 无持续异常；
- [ ] 内核封禁：`ipset list frpwaf_block` 条目数与预期一致（插件端「IP 名单 / 封禁」页的内核封禁卡片）；
- [ ] 连接日志/封禁管理无异常来源；
- [ ] `frps.toml` 中 `name="frpwaf"` 的 `addr` 与 WAF 实际端口一致；
- [ ] 默认账号已修改（若非首次部署）；
- [ ] 磁盘空间充足（`data/` 会增长，日志有上限）。

## 五、约束与本项目设计的一致性

| 约束 | 代码/文档中的体现 |
|---|---|
| frps 日志不动 | `frp.py` 只读写 `frps.toml`，迁移仅移除**新版不认的遗留字段**，不碰 `[log]` |
| 不擅自升级 frps | `frp_install_start` 需显式触发；升级前自动备份；失败自动回滚 |
| 不擅自发布 | 文档明确「发布须经同意」；未经指示不得 commit/tag/push/release |
| 不泄露密码 | 配置 `600`；`/api/config` 过滤机密；`ai_api_key` 掩码 `******`；`.gitignore` 排除 `data/`、`*.bak.*`、`*.premigrate.*` 等含密钥文件 |
| auto_ban 默认关 | `config.DEFAULTS["auto_ban_enabled"]=False` |
| fail-closed 处置 | `uninstall_waf`/`uninstall.sh` 先移除回调再停 WAF；本文 §三 |
