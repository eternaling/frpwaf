# 14 · 运维注意事项与约束

> 本文汇总本项目的**不可触碰约束**、**危险操作清单**与**fail-closed 处置**。
> 这些约定来自真实事故与明确要求，务必遵守。

---

## 一、不可触碰的约束（硬性）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **不要改动 frps 日志配置** | frps 的 `[log]` 段落保持原样，不修改、不迁移、不重写 |
| 2 | **不要擅自升级 frps 版本** | 升级 frps 属高危动作，**须经明确同意**后再执行 |
| 3 | **不要擅自调整面板暴露** | 面板的对外暴露/端口变更须经明确同意。默认已收紧为仅本机 `127.0.0.1`，未经明确同意**不得**改成 `0.0.0.0` |
| 4 | **不要擅自发布版本** | 「**我有让你发布版本了你再发布，别一直发布**」——未经指示不得 commit/tag/push/release |
| 5 | **不泄露真实账号密码** | 「**别在 git 漏出我真实的账号密码呀**」——配置/文档/提交中一律用占位或掩码 |
| 6 | **不打印/暴露密钥** | 不打印 `ANTHROPIC_AUTH_TOKEN`；AI 密钥读取时掩码 `******` |
| 7 | **`auto_ban` 默认保持关闭** | 默认 `auto_ban_enabled=false`，防止误封正常用户 |
| 8 | **全程中文回复** | 面向用户的一切说明使用中文 |
| 9 | **默认面板账号 `admin` / `123456`** | 代码内保持默认（未经同意不改默认值）；但首次登录会被强制改密（`password_changed`） |
| 10 | **禁止 SFTP/直传生产目录** | 不得用 SFTP/文件管理器/`scp` 直接往 `/opt/frpwaf` 或插件目录写文件。Windows 侧工具会把文件写成服务器上**不存在的 uid**（如 `197609`），`ls -l` 只显示数字、`find -user` 按名筛不到，权限审计全部失效，且将来一旦给 unit 加 `User=` 或让面板子进程降权，就立刻读不到代码。正确入口只有两条：**上传 zip 安装** 或 **面板内在线升级**。若必须手工传，传完立即 `chown -R root:root` 并校验（`find <dir> -uid 197609` 必须为空） |
| 11 | **生产目录不再需要 git** | `/opt/frpwaf/.git` 已于 2026-11-28 移出（移了但 `.git` 被当成工作副本在用：停在旧提交、`git status` 显示假差异，而 `git checkout .` / `git clean -fd` 会直接删掉正在运行的代码）。生产由发布包驱动，需要版本对照时看**插件目录**的 `info.json`（发布包版本）与 `/opt/frpwaf/app/__init__.py` 的 `__version__`（运行代码版本），再比 md5；`/opt/frpwaf` 根目录不保留 `info.json` 副本 |

## 二、危险操作清单（⚠️）

### 2.1 严禁 `pkill` / `pkill -f`

**本项目守护进程运行命令是 `python -m app.daemon`。**

```bash
# ❌ 绝对禁止：
pkill -f "app.daemon"     # 会匹配并杀掉生产 WAF 进程（曾造成生产事故）
pkill -f frpwaf
```

**只允许按精确 PID 终止**，或使用服务脚本：

```bash
frpwaf stop               # ✅ 推荐
kill <精确PID>            # ✅ 已知 PID 时
```

> 隔离实例、临时进程同样按精确 PID 关闭。

### 2.2 停用 / 卸载顺序（fail-closed）

**必须先移除 frps 的 `[[httpPlugins]]` 回调配置并重启 frps，再停 WAF。**
顺序颠倒会导致 frps 一直回调已停止的 WAF → **fail-closed 全线拒绝用户连接**。

本项目已在 `uninstall_waf()`、`uninstall.sh` 中按此顺序实现，手动操作时务必遵守。
配置校验或 frps 重启失败时中止卸载、保留 WAF；WAF 停止失败时尝试从备份恢复回调。

### 2.3 改 `frps.toml`

- 改前 `frp.py` 会自动 `cp` 备份；改后 `frps verify` 校验，失败自动回滚。
- **不要**手工删除/破坏 `[[httpPlugins]]` 以外的既有段落。
- 改完必须 `frps restart` 才生效。

### 2.4 改 `data/frpwaf.json`

- 文件含 `secret`/`admin_password`/`ai_api_key`，权限 `600`。
- 插件端 `_set_cfg` 在读取失败时**拒绝保存**，防止抹除敏感字段。
- 手工编辑务必保持合法 JSON，否则读取回退空配置。

### 2.5 内核封禁

- 关闭 `fw_sync_enabled` 会 `teardown()` 清理 iptables/ipset。
- 不要手工在 `FRPWAF_BLOCK` 链里加自定义规则（会被对账逻辑覆盖/清理）。
- `iptables -F` / `iptables -X`（不带链名）属全局危险操作，**禁止**。

## 三、fail-closed 处置手册

### 3.1 原理

frp `httpPlugins` 为 **fail-closed**：`frps.toml` 有回调配置、而 WAF 不可达 →
frps **拒绝所有**新用户连接。

### 3.2 WAF 挂了，业务全断，怎么快速恢复？

**两条路**：

**A. 尽快恢复 WAF**（保住防护）：
```bash
frpwaf status
frpwaf restart          # 或 frpwaf start
# 确认监听：ss -lntp | grep -E '7080|7082'   # 7080 面板、7082 回调
# 确认回调：curl -s -X POST 'http://127.0.0.1:7082/frp/handler?op=NewUserConn' \
#   -H 'Content-Type: application/json' -d '{"content":{"remote_addr":"127.0.0.1:1"}}'
```

**B. 临时解除（牺牲防护换可用性）**：移除回调配置并重启 frps：
```bash
# 备份
cp -a /usr/local/frps/frps.toml /usr/local/frps/frps.toml.bak.$(date +%F-%H%M%S)
# 手动删除 name="frpwaf" 的 [[httpPlugins]] 块（见下方说明），或直接运行卸载脚本
/etc/init.d/frps restart
```
> 说明：插件端**没有**「移除回调」按钮，只有「注入回调」（`apply_to_frps`）。
> 移除回调的正规途径是**卸载**（`uninstall_waf()` / `uninstall.sh`，会自动移除回调并重启
> frps），或按 [02 §3](02-目录结构与安装部署.md) / `uninstall.sh` 中的块删除逻辑手动操作。
> 恢复 WAF 后再用插件端「frps 集成 → 注入」重新挂上回调。

### 3.3 决策异常 vs 进程不可达

- **单次决策异常** → `daemon` 内 `allow=True`（fail-open），只放行本次，不影响整体；
- **进程不可达** → frps fail-closed 全拒。
  这是**有意**设计：小 bug 不炸业务，但防护进程没了就不放流量。

## 四、日常运维检查清单

- [ ] `frpwaf status` 为 running；`ss -lntp | grep 7080` 有监听；
- [ ] `data/frpwaf.log` 无持续异常；
- [ ] 内核封禁：`ipset list frpwaf_block` 条目数与预期一致（插件端「IP 名单 / 封禁」页的内核封禁卡片）；
- [ ] 连接日志/封禁管理无异常来源；
- [ ] `frps.toml` 中 `name="frpwaf"` 的 `addr` 与 WAF 实际端口一致；
- [ ] **改完 `app/` 或 `frpwaf_main.py` 后，除重启 `frpwaf` 外还要重启面板进程**：
      `systemctl restart bt`。宝塔面板是常驻进程，磁盘换文件不会让它重载已 import 的
      模块——守护进程已是新代码（命令行验证全对）、插件端页面却仍拿到旧模块的数据
      （新字段缺失、新卡片不出现）就是这一条没做。插件的 mtime 签名重载靠文件 mtime
      比对，而发布包内所有条目使用固定时间戳（见 `scripts/make_plugin_zip.py`），
      解压后与上一版完全相同 → 它识别不到变更，**不能指望自动重载**。
      影响面：面板 UI 中断数秒；WAF 防护与 frps 隧道**不受影响**（独立进程）。
      验证：`/www/server/panel/pyenv/bin/python -c "import sys;sys.path.insert(0,'/opt/frpwaf');import app.store as s;print(sorted(s.stats().keys()))"`
      应含 `conns_24h` / `conns_total` / `bans_24h`（v1.5.4 起）；
      命令有而页面无 → 面板进程未重启（见 [02 §4.1](02-目录结构与安装部署.md)）；
- [ ] 默认账号已修改（若非首次部署）；
- [ ] 面板点「在线升级」/「测试连接」后**不要因为转圈就重复点**：这两个操作已改为
      「提交 + 轮询」，下载/模型回包可能持续几十秒到 2 分钟，且升级末尾会重启服务；
      进度可直接 `cat data/job_upgrade.json` / `data/job_ai_test.json` 查看；
      出现「任务状态已中断」时先刷新页面确认版本号与 `data/frpwaf.log`，再决定是否重试
      （见 [11 §6.5](11-开发运维与常见问题.md)、[12 Bug AA](12-Bug修复记录.md)）；
- [ ] 磁盘空间充足（`data/` 会增长，日志有上限）；
- [ ] **数据备份在跑**：`/usr/local/bin/frpwaf-databak.sh` 每天 03:23 由 `/etc/cron.d/frpwaf-databak` 触发，
      产物在 `/www/backup/frpwaf-data/`，保留最近 7 份。检查：`ls -lh /www/backup/frpwaf-data/`
      与 `tail /var/log/frpwaf-databak.log`；**恢复演练**：解开一个包 → `sqlite3 frpwaf.db "PRAGMA integrity_check"`
      应为 `ok`，且 `MANIFEST.txt` 里的各表行数与线上一致；
- [ ] **属主无污染**：`find /opt/frpwaf /www/server/panel/plugin/frpwaf -uid 197609` 输出必须为空。
- [ ] **生产目录形状**：`ls -A /opt/frpwaf` 应只有 `app data web`。出现 `build.sh`/`docs`/`tests`/`frpwaf_main.py`/`index.html`/`info.json`/`install.sh` 等说明被发布包覆回去了（2026-11-28 起改为纯发布包驱动，见 [02 §2.0](02-目录结构与安装部署.md)）；
      同理 `find /opt/frpwaf -maxdepth 1 -name '*.py'` 应为空。
- [ ] **运行层不堆面板载荷**：`ls /opt/frpwaf` 不应出现 `frpwaf_main.py`、`index.html`、
      `info.json`、`install.sh`、`uninstall.sh`、`frpwaf.init`、`frpwaf.service`——
      这 7 个只有插件目录那份在被读（面板入口、安装脚本、守护进程都不读运行目录里的这份）。
      在线升级会顺带清掉历史副本；若仍存在，确认是不是升级没走到覆盖那一步，
      手工 `rm` 那 7 个即可（**别**删 `app/`、`web/`、`data/`）。

## 五、约束与本项目设计的一致性

| 约束 | 代码/文档中的体现 |
|---|---|
| frps 日志不动 | `frp.py` 只读写 `frps.toml`，迁移仅移除**新版不认的遗留字段**，不碰 `[log]` |
| 不擅自升级 frps | `frp_install_start` 需显式触发；升级前自动备份；失败自动回滚 |
| 不擅自发布 | 文档明确「发布须经同意」；未经指示不得 commit/tag/push/release |
| 不泄露密码 | 配置 `600`；`/api/config` 过滤机密；`ai_api_key` 掩码 `******`；插件端 `get_admin`/`get_waf_info` 密码同样掩码不回显；`.gitignore` 排除 `data/`、`*.bak.*`、`*.premigrate.*` 等含密钥文件 |
| auto_ban 默认关 | `config.DEFAULTS["auto_ban_enabled"]=False` |
| fail-closed 处置 | `uninstall_waf`/`uninstall.sh` 先移除回调再停 WAF；本文 §三 |

---

> 若上述任一约束需要变更，**先与用户确认**，不要擅自行动。
