## 1. 为什么要发这一版

v1.5.3 之后 `main` 上又合入 11 个提交（含 5 个合并提交），包括概览指标口径改造、
概览排版修复、一套全新的系统端口防护模块与它的设置页 UI，以及一处会让面板保存
完全无反应的声明缺失修复——**都没有随之发版**。

与前几版不同，本版的紧迫性不在「版本落后」，而在**功能丢失**：

- `app/sysdetect.py` 是**全新文件**，v1.5.3 的发布包里根本没有它。换机器安装或走
  「在线升级」装回来的包不含这个文件，系统端口防护这一整块能力会**直接不存在**。
  前几版的问题是「装回旧行为」，本版不发的代价是「装完少一个模块」。
- 插件端设置页的 `FW_POLICY_STR` 声明被误删后，「保存策略」按钮**点了没任何反应**
  （不报错、不提示、配置也不变），只能靠新包下发修复，无法在运行期热修。

## 2. 本版包含的改动

### 2.1 概览口径（两端一致）

概览卡片此前有三处「读出来的数字不成立」的问题，本版逐项改成可解释的口径。

**① 连接数改「近 24 小时 + 真累计」**

原卡片主值是「日志窗口内的连接数」，而该值受连接日志保留行数裁剪，日志装满后它
就不再增长（线上曾出现 50001 与上限 50000 几乎相等的读数）。现在：

- 主值改为**近 24 小时连接数**：滑动窗口统计，不随日志裁剪饱和；
- 副行改为**真累计**：取自数据库自增序列（该计数器只增不减，删行与库整理都不会
  回退），因此它包含已被裁剪掉的历史条目，是唯一不依赖额外建表/迁移的「真累计」口径；
- 旧字段仍保留在接口返回里（只增不改），老前端与第三方脚本读取不受影响。

**② 封禁卡改为状态型指标**

原卡片把「永久名单条目数」与「临时封禁数」相加后作为「当前生效」展示，而黑名单
条目本身就只增不减（线上 499 条最早可追到上个月），于是同一个数字换个名字继续
冒充「当下威胁规模」。现在把趋势与存量分开表达：

- 主值：**近 24 小时新增封禁**（临时封禁写入 + 永久名单写入各计一条）；
- 副行：**黑名单 N 条 · 临时封禁 M 条生效**，并明确「N 是名单规模，不等于生效封禁数，
  真正生效中的封禁只看『生效封禁』卡片」。

**③ 新增「内核层已丢弃」卡片**

展示内核链累计丢弃的包数与字节数（IPv4 + IPv6 合计，取精确计数而非人类可读缩写），
副行为**近 1 分钟速率**。两点保护：

- 速率采样遇到计数回退（规则重建、链被清空、集合丢失修复等会让累计值归零的场景）时
  丢弃旧样本、以本次为新基线并显示 `—`，**不会出现负数**；
- 拦截页模式（REDIRECT）下不产生 DROP 计数，此时静默为 0 并在文案里标注模式。

**④ 概览排版修复**

统计口径说明原先被拼进卡片网格容器，而它带的是 flex 属性（在 grid 容器里无效），
结果落进最窄一列、被压成逐字竖排，并把整行卡片高度从 117px 撑到 524px。
现在说明移出网格、在卡片区之后**整宽展示**；卡片最小列宽同步从 130px 提到 170px，
1200px 左右视口不再挤成 8 列。

### 2.2 按来源归因（内核封禁）

**① 内核封禁集合启用 counters**

集合创建时带上 counters，即可读到每个被拦来源的命中包数与字节数，用于「来源识别」
展示（谁在持续被拦、量级多大）。归因接口带短 TTL 缓存，面板放在「内核封禁」页的
折叠块里，不占用概览版面。

**② 存量集合一次性重建迁移**

`ipset` 不支持给已存在的集合补加 counters（`create -exist` 会静默忽略），因此存量
集合必须重建：

- 先在旁边建**临时集合**（带 counters）并把当前要下发的成员一次性填满；
- 再按「先摘引用规则、最后摘 DROP，挂回时 DROP 最先挂」的顺序销毁旧集合并改名顶上；
- 切换窗口只有「摘 DROP → 挂回 DROP」之间的几条命令，**毫秒级**，且应用层仍按
  数据库状态拒绝连接，防护不中断；
- 任一步失败自动兜底：重建集合并按数据库快照**全量回填**成员、重挂规则，绝不留下
  空集合；内核/`ipset` 版本不支持 counters 时保持旧格式并记一条日志，
  拦截能力不受影响。

迁移只在审计轮（启动首轮与每 600 秒）执行，不进 10 秒级的稳态同步路径，
「稳态零外部调用」的前提继续成立。归因读不到时面板显示「未启用」，不做假数据。

### 2.3 系统端口防护（全新模块）

**为什么需要**：`22` 等系统端口不过 frps 回调，既不进连接日志、也不经过准入决策，
WAF 对它们完全不可见；而内核封禁是按来源 IP **不限端口**丢包的。也就是说
「拦住某个来源对 22 端口的尝试」在机制上早已具备，缺的只是**检测**。本版补这一层，
不改动封禁链路与决策路径。

**① SSH 登录成功写入登录信任（安全前提）**

原实现只有「面板登录成功」与「进入插件端某页」两处会写登录信任，**没有任何 SSH
登录路径会写**。而内核 DROP 是全端口的——一旦某个来源被误封，连 22 端口都进不去。
现在 SSH 认证通过（公钥 / 密码 / keyboard-interactive）即写入登录信任；失败类事件
（认证失败、无效用户、连接中断、认证次数超限）只做计数，**永不写信任**。
该开关默认开启，且**不依赖检测开关**（属安全前提，即使检测关闭也生效）。

**② 认证日志增量检测**

按「inode + 读偏移」增量读取系统的认证日志（默认自动探测常见路径，可用配置指定）：

- 轮转（rename + create）与截断（copytruncate / 人工清空）都能识别，从头重读并记一条
  运行日志，不会漏也不会重复计数；
- **首次启动定位到文件末尾，历史行一律不计数**——否则开服瞬间就把过去几天的记录
  算成一次批量封禁；检测关闭期间同样只把位置推到末尾，再次开启不补算历史；
- 单轮有行数与字节上限（性能红线），半行不消费，来源地址一律先做合法性校验。

**③ 默认关闭、默认只观察**

阈值只能从真实分布里定，所以在拿到观察数据之前不把开关做成「随手可点的按钮」：

- `sys_detect_enabled` 默认 **false**（内核 DROP 是全端口的，误封会把管理者锁在门外，
  必须显式开启）；
- `sys_detect_dry_run` 默认 **true**（只记录不处置），面板上关闭它需要二次确认并写审计；
- 只有超阈值才处置，且处置走**临时封禁**（带 TTL，到期自动解除，进程异常退出后内核
  条目也按 timeout 消失），不自动升级为永久名单；单条时长有上限，防止配置写错变成
  事实上的永久封禁。

**④ 六道豁免**

按「白名单 → 登录信任 → 可信回源段 → 人工保护名单 → 活跃 SSH 会话 → 非公网来源」
的顺序逐层短路：

| 豁免 | 说明 |
|---|---|
| 白名单 | **无条件生效**，不跟随「白名单开关」（该开关默认关闭，若跟随就会出现「已加白名单仍被拦」） |
| 登录信任 | 命中的来源在有效期内一律跳过；SSH 登录写入的那份自动被认账 |
| 可信回源段 | 人工配置的回源网段 + 自动学习到的回源网段，避免把回源节点当成异常来源 |
| 人工保护名单 | 面板可维护的「永不封禁网段」，校验不通过整批拒绝 |
| 活跃 SSH 会话 | 该来源当前存在已认证的会话时不处置，避免把正在操作的人踢下线 |
| 非公网来源 | 回环、链路本地、私网、保留、组播地址一律不处理 |

另有一道**全局熔断**：每小时处置次数超过上限即停止处置（应对整段被批量探测时的
连带误伤），上限可配，`0` 表示不熔断。

**⑤ 观察记录独立存储**

观察记录写入独立的表，**不写连接日志**：连接日志会按来源聚合后送来源识别审查，
而系统端口事件没有代理名与代理类型，混进去既干扰判据，也会让代理统计出现假条目。
观察记录有保留条数上限，由后台周期任务裁剪。

### 2.4 面板

- **设置页新增「系统端口检测」卡片**（两端字段与文案一字不差）：启用开关、观察模式、
  失败次数阈值（`0` = 只计数不处置）、计数窗口、封禁时长、每小时上限、轮询间隔、
  单条封禁上限、永不封禁网段、SSH 登录写信任开关。保存只提交 `sys_*` 字段，
  合并写入、不动其它配置键。
- **设置页新增「观察记录」**：时间 · 来源 · 归属地 · 命中/窗口 · 处置 · 原因，支持按
  来源与处置结果筛选与分页；顶部汇总最近 24 小时的「本应处置 / 实际处置 / 被豁免
  （按原因分组）」，汇总**不跟随筛选条件**——它要回答的是「阈值定得合不合适」。
- **修复「保存策略」静默失效**：`FW_POLICY_STR` 声明在一次改动中被误删，
  而读取与保存策略仍在调用它，于是两个函数执行到该行即抛异常——读取时字符串字段
  永远回显为空，保存时**请求根本没发出去**，整个保存链路静默死掉。本版恢复该声明、
  把新增的字符串字段一并加入，并补了回归用例钉住「声明必须存在」。

## 3. 升级注意

1. **`log_max_rows` 不会自动跟随新默认值**：代码默认已是 200000，但配置迁移只给
   **缺失键**补默认值，文件里已存在的键不跟随。线上旧值若仍是 50000，需手工把
   `data/frpwaf.json` 的 `log_max_rows` 改为 `200000` 后重启服务（改大改小都安全，
   裁剪逻辑不假设任何固定上限）。
2. **`sys_*` 全部默认关闭**：`sys_detect_enabled=false` 时只是多一个空闲后台线程
   （每 5 秒一次状态检查，不读文件内容、不写库），默认行为没有任何变化。
   唯一默认开启的是「SSH 登录成功写登录信任」，可用 `sys_trust_ssh_login=false`
   或 `trust_login_ttl=0` 关闭。
3. **启用前先观察**：建议先 `sys_detect_enabled=true` 并**保持观察模式**跑几天，
   在观察记录里看被拦来源的分布与密度，再决定阈值，最后才关闭观察模式。
   建议同时把自己的常用出口段写入「永不封禁网段」。
4. **内核封禁集合的 counters 迁移在首次同步时自动完成**，无需人工干预；
   迁移失败有自动回填兜底，防护不中断。迁移后「来源计数」由「未启用」变为「已启用」。
5. **生效方式**：本次是 Python 代码改动，需**重启 frpwaf 服务**一次（无热加载）。
   若同时更新了 `app/` 下的代码或 `frpwaf_main.py`，**还需重启面板进程**
   （见 [02 §4](02-目录结构与安装部署.md) 与 [14 §四](14-运维注意事项与约束.md)），
   否则插件端读到的是面板进程里缓存的旧模块。
6. **无破坏性变更**：无配置项删除或改名；`stats()` 只增字段、旧字段全部保留；
   新增的观察记录表用 `CREATE TABLE IF NOT EXISTS` 建，新旧库同一路径生效。
