AI 自动 IP 审查 -

AI 审查的模型/密钥/调度配置在插件端「AI 审查」页维护；此处可查看最近审查记录并手动触发。

AI 接口安全 默认允许内网地址

默认开启：AI 网关常是内网自建（如 http://127.0.0.1:3000），开启即可直接使用。 关闭后 AI 接口只能访问公网地址，内网自建的 AI 网关将不可用（指向本机/内网的接口地址会保存被拒、测试连接失败）。 无论开关如何，链路本地与云元数据地址（169.254.0.0/16、fe80::/10）始终拒绝。

内核级封禁 -

内核级封禁（ipset+iptables）把命中封禁的 IP 在内核层直接丢包；关闭后若拦截页开启，则改为 REDIRECT 展示封禁页。需 root + ipset/iptables。集合启用 counters 后可展开「丢弃来源 Top」看谁被丢得最多（需先完成一次性集合重建；重建期间拦截不断）。

服务控制 高危操作，将写入审计日志

停止/重启后网页端将短暂不可访问；请到服务器执行 /etc/init.d/frpwaf start 重新启动。程序升级请用「关于」页的 GitHub 在线升级。

永久黑名单

        

        
白名单命中的 IP 不受上述自动封禁影响（需已启用白名单开关）；CC 检测依赖 frp NewUserConn 回调，仅对 https/tcpmux 代理生效（http 类型不触发回调，纯 http 代理请以限速/名单手段为主）；敏感服务检测仅针对非 HTTP 类代理，代理名按分隔符匹配关键字（ssh / mysql / redis / rdp / mongo / postgres / elastic / telnet / smb / vnc / ftp），wordpress 这类含子串的普通名不会误判。爆破封禁在黑名单开关关闭时自动降级为临时封禁。

误伤提示：出口 IP 变化的真实用户（移动网络切换、动态 IP、CDN 回源）可能被拒。建议先在「连接日志 → 突发观测」观察 1-2 天，确认流量性质且可接受偶发误伤后再启用；白名单 IP 不受影响。

        

        
系统端口检测 非 frp 端口（22/6379/8888 等）的来源识别，默认关闭 + 默认只观察

        

        
从系统认证日志（auth.log / secure）增量识别非 frp 端口上的敏感端口探测与高频登录失败，按「单来源滑窗计数」判定，达阈值才处置。关闭时完全不做统计。

        

        
关闭观察模式 = 真的会封 IP：处置经内核下发，DROP 是全端口的——一旦某个来源被误判，22 / 7080 / 8888 会一起进不去，面板也打不开，只能上云厂商控制台或 VNC 救机器。
所以关掉前请：① 把常用出口 IP 写进下面的保护名单；② 先看「观察记录」里最近 24 小时的「本应封禁」量是否可信。切换时会再弹一次二次确认。
